## 为什么重要
“你会如何衡量 Google、Amazon 或 Airbnb 的搜索质量？”这类问题把产品感与排序评估结合在一起。好的回答会结合离线相关性指标（NDCG、MRR）、线上行为（成功率、放弃率、改写率）以及严谨的实验设计。模型侧的细节可参见推荐系统评估相关课程。

## 概念
**离线（人工或标注的相关性判断）**：
- **Precision@k**：前 $k$ 个结果中相关的数量 / $k$。
- **MRR**（平均倒数排名）：$1/\text{第一个相关结果的排名}$ 的平均值。适合只有一个正确答案的导航型查询。
- **NDCG@k**：处理分级相关性与位置。设第 $i$ 位的增益为 $rel_i$，

$$DCG@k = \sum_{i=1}^{k} \frac{rel_i}{\log_2(i+1)},\qquad NDCG@k = \frac{DCG@k}{IDCG@k}$$

其中 IDCG 是理想排序的 DCG（有些团队用 $2^{rel}-1$ 作为增益）。它的取值在 [0, 1]，可跨查询比较。
- 注意事项：标注成本、标注者分歧、标签过时，以及查询集必须有代表性（头部、腰部、长尾）。

**线上（行为）**：
- **点击率**噪声大：点击不等于满意。需配合**停留时长**或**长点击**（用户没有退回）。
- **放弃率**（没有点击）、**改写率**（用户重写查询）、**首次点击时间**、**零结果率**、来回跳转（pogo-sticking）。
- **任务成功**：购买、预订或明确的“有帮助”。电商还要看加购率、转化率和每次搜索收入。
- 按查询类型（导航型、信息型、交易型）和头部/长尾切片。“好的放弃”（答案已显示在结果页）看起来像坏的放弃。

**线上实验**：
- 对用户级成功指标做 **A/B 测试**：可靠，但需要大量流量。
- **交错（interleaving）**（如 team-draft）：把两个排序器的结果混成一个列表，把点击的功劳记给对应的排序器。灵敏度高得多（通常所需查询量少 10-100 倍），适合比较排序器，但不衡量绝对指标或长期效应。
- **并排（side-by-side）**人工评估，用于发现质性退化。

**护栏**：延迟（p95）、每次搜索的广告或收入、多样性、对卖家的公平性以及安全性。

## 示例讲解
**离线。**对某个查询，排序器返回四个结果，分级相关性为 $[3, 2, 0, 1]$（3 = 完美）。

- $DCG@4 = 3/\log_2 2 + 2/\log_2 3 + 0/\log_2 4 + 1/\log_2 5 = 3 + 1.2619 + 0 + 0.4307 = 4.6926$。
- 理想顺序 $[3, 2, 1, 0]$：$IDCG@4 = 3 + 1.2619 + 1/2 + 0 = 4.7619$。
- $NDCG@4 = 4.6926 / 4.7619 \approx$ **0.985**。如果把 1 放到 0 前面，结果就是 1.0。

**线上。**100,000 次搜索（示意数据）中，82,000 次有点击（放弃率 18%），15,000 次在 30 秒内被改写（15%），61,000 次有点击且停留超过 30 秒（成功率 61%）。

用 team-draft 交错对 20,000 个有点击的会话测试新排序器：排序器 B 胜 5,600 次，排序器 A 胜 4,400 次，10,000 次平局。排除平局后，B 的胜率为 5,600 / 10,000 = **56%**。这显著高于 50%（标准误约为 $\sqrt{0.25/10{,}000} = 0.5\%$，所以 z = 12）。

**解读**：用户更偏好 B。上线前，用成功率的 A/B 测试确认，并检查护栏：延迟、每次搜索收入，以及长尾查询切片（新排序器常在此退化）。

> [!TIP] 面试技巧
> - 结合三层：离线相关性（NDCG、MRR）、线上行为（成功率、放弃率、改写率）和实验（A/B、交错）。
> - 说明仅看点击为什么会误导（位置偏差、标题党、好的放弃），并提出停留时长或任务成功作为更好的信号。
> - 按头部与长尾查询以及意图切片，并说明延迟、每次搜索收入等护栏。
