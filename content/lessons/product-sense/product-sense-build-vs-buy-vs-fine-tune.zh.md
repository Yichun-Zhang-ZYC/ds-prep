## 为什么重要

每个 AI 功能都从同一个问题开始：调用托管的模型 API、微调一个较小的模型，还是自己训练并部署？面试官想听到带数字的决策框架，而不是“开源更便宜”这类口号。正确答案会随请求量、质量差距、隐私和团队规模而变化。

## 概念

把它看成一个阶梯：只有在下一级未能满足经过测量的要求时才往上爬：

1. **提示托管 API**（购买）：无需训练，上线最快，按 token 付费，质量、延迟和下线由供应商控制。
2. **加入检索（RAG）和更好的提示词**：解决知识缺失和时效性，无需训练。
3. **微调**（托管模型或开源模型）：解决*行为*、风格、格式和领域特定技能；常常能让小模型在窄任务上追平大模型，降低成本和延迟。它不能可靠地注入新的事实。
4. **自托管开源模型**：在规模化时掌控数据、延迟和成本；GPU、服务部署和值班都由你负责。
5. **从零训练**：除基础模型实验室外几乎都不合理。

决策因素：在你自己评测集上的**质量差距**、**请求量**（盈亏平衡点）、**数据敏感性**和驻留要求、**延迟**需求、**差异化**（这是你的护城河吗？）、**团队**（有没有 ML 和基础设施工程师？）以及**锁定 / 切换成本**。

设 API 的单次请求成本为 $c_a$，自托管的月固定成本为 $F$、可变成本为 $c_s$，盈亏平衡请求量为：
$$V^* = \frac{F}{c_a - c_s}$$
月请求量低于 $V^*$ 时购买更便宜；高于它且质量相同时自建更划算。$F$ 中要包括人力成本，而不只是 GPU。

## 示例讲解

某产品每月发送 100 万次请求，每次 1,500 个输入 token 和 300 个输出 token。托管 API 每百万输入 token 收费 \$3，每百万输出 token 收费 \$15（示意价格）。

每次请求：$1500 \times 3/10^6 + 300 \times 15/10^6 = 0.0045 + 0.0045 = \$0.009$。每月：\$9,000。

在 2 块 GPU 上运行微调后的小模型，成本为 $2 \times 720 \text{ 小时} \times \$2.50 = \$3{,}600$，再加上每月约 \$6,000 的工程人力，所以 $F = \$9{,}600$，$c_s \approx 0$。盈亏平衡点：$9{,}600/0.009 \approx 107$ 万次请求/月。

在 100 万次请求时，购买（\$9,000）略便宜，而且没有运维负担，所以先用 API。到 300 万次请求时，API 要 \$27,000，自托管约 \$9,600（假设 2 块 GPU 扛得住），所以功能被验证后再微调并自托管。切换前要在评测集上重新检查质量；换成更差的模型省下的成本不算真正的节省。

> [!TIP] 面试技巧
> - 给出阶梯（提示词、RAG、微调、自托管），并说明每一级解决什么问题。
> - 计算盈亏平衡点时一定要包含人力成本，并在自己的评测集上保持质量相当。
> - 把锁定、模型下线和数据隐私作为非成本因素提出来。
