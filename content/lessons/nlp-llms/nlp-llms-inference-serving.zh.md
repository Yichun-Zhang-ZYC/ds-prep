## 为什么重要
服务成本往往远超训练成本。面试官会考察你是否知道解码为何受内存带宽限制，连续批处理和 PagedAttention 如何提高吞吐，以及延迟与吞吐的权衡。

## 概念
**每个请求有两个阶段**：
- **预填充（Prefill）**：并行处理整个提示并构建 KV cache。计算受限。决定 **TTFT**（首 token 时间）。
- **解码（Decode）**：每步生成一个 token，每次都要读取全部权重和 KV cache。**受内存带宽限制**。决定 **TPOT / ITL**（每个输出 token 的时间）。

**指标**：TTFT、TPOT、端到端延迟（p50/p99）、吞吐（每 GPU 每秒 token 数）、每百万 token 成本。批越大吞吐越高，因为每步对所有序列只读一次权重，但排队和单步耗时会增加延迟。

**批处理**：
- **静态批处理**：等待凑成一批，运行到*最长*序列结束；已完成的槽位空闲。
- **连续（in-flight，迭代级）批处理**：每个解码步之后，移除已完成序列并接纳新请求。在输出长度不一的情况下 GPU 利用率高得多。
- **分块预填充**：把长提示切成块，与解码步混合执行，避免阻塞正在运行的请求。

**内存管理**：
- 朴素的服务器按最大长度预留连续的 KV 空间，因碎片和过度预留浪费 60-80%。
- **PagedAttention（vLLM）**：把 KV 存放在固定大小的块中（例如 16 个 token），通过每个序列的块表寻址，类似操作系统的虚拟内存。浪费降到几个百分点，因此可容纳更多并发序列。块还可以共享，用于**前缀缓存**（公共系统提示），并通过写时复制支持并行采样或束搜索。

**其他手段**：FlashAttention 内核、量化（权重和 KV）、**推测解码**（小的草稿模型提出 token，大模型一次验证多个，输出分布不变）、超出单 GPU 的模型用张量/流水线并行，以及请求路由或自动扩缩容。引擎：vLLM、TensorRT-LLM、SGLang、TGI。

## 示例讲解
一个 7B 的 fp16 模型有 14 GB 权重。在内存带宽 2 TB/s 的 GPU 上，一个解码步至少要读取 14 GB：$14 / 2000 = 7$ ms，因此单个序列约 143 token/s。

批中有 30 个序列时，每步仍然只读一次权重（KV 读取略有增加），吞吐约为 $30 / 0.007 \approx 4{,}300$ token/s，约 30 倍，而每个用户仍然只看到约 7 ms 每 token。批大小受 KV 内存限制：每个 token 0.5 MB，4k token 的序列占 2 GB，所以装有 14 GB 权重的 80 GB 显卡可容纳约 $(80 - 14)/2 \approx 33$ 个序列，而 PagedAttention 才能让你真正逼近这个上限。

> [!TIP] 面试技巧
> - 区分预填充（计算受限，TTFT）与解码（内存受限，TPOT），并把批处理与后者联系起来。
> - 各用一句话解释连续批处理和 PagedAttention，以及它们解决的问题。
> - 一定要提到延迟与吞吐的权衡，并指出 TTFT 和 p99 是面向用户的指标。
