## Why it matters
A pre-trained LLM only continues text; it does not follow instructions. Instruction tuning (supervised fine-tuning, SFT) is the first step that turns a base model into an assistant, and interviewers ask what it changes, how the loss is computed and what data it needs.

## Concept
**Supervised fine-tuning** trains the base model on (instruction, response) pairs with the same next-token cross-entropy as pre-training, but:
- Text is wrapped in a **chat template** (special tokens marking system / user / assistant turns) so the model knows where to answer and when to stop (EOS).
- The loss is computed **only on response tokens**. Prompt tokens are masked (label `-100` in PyTorch/HF), so the model learns to *answer*, not to imitate user prompts.
- Typical recipe: 1-3 epochs, small learning rate ($10^{-5}$ to $2 \times 10^{-5}$), short sequences **packed** to fill the context window.

**Data**:
- **Quality beats quantity**: LIMA showed ~1,000 carefully curated examples give a strong chat model.
- Sources: human-written demonstrations, task collections reformatted as instructions (FLAN), and **synthetic** data generated by a stronger model (Self-Instruct, Alpaca; check the teacher's license).
- Diversity of tasks and formats matters more than volume of near-duplicates.

**What it does**: mostly teaches *format, style and following instructions*, and generalizes to unseen tasks (zero-shot). It adds little new *knowledge*. Fine-tuning on facts the model does not already know can teach it to confidently guess, **increasing hallucination**.

**Limits**: SFT only imitates demonstrations; it cannot say which of two acceptable answers is *better*. That is what preference tuning (RLHF / DPO, next lesson) adds.

## Worked example
Prompt tokens `[11, 12, 13]`, response tokens `[21, 22]`, EOS id `2`.
- `input_ids = [11, 12, 13, 21, 22, 2]`
- `labels    = [-100, -100, -100, 21, 22, 2]`

Per-token losses on the three unmasked positions are $1.2, 0.6, 0.3$. The SFT loss is their mean, $2.1 / 3 = 0.7$. Averaging over all six positions (wrongly including the prompt) would dilute the signal and train the model to predict user text.

> [!TIP] Interview tips
> - Say "loss only on assistant tokens" and "chat template with EOS"; these are the details people forget.
> - Frame SFT as teaching behavior, not knowledge; use RAG or continued pre-training to add knowledge.
> - Mention data quality and diversity over size (LIMA), and synthetic data risks (errors, license, mode collapse).
