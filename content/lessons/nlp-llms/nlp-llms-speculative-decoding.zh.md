## 为什么重要
自回归解码受内存带宽限制：每个 token 都要完整读取一遍权重，而 GPU 算力却闲置。推测解码把这部分富余算力转化为更低的延迟，同时不改变输出分布。它是考察“你会不会推理加速比”的热门问题（背景见“推理服务”和“解码策略”）。

## 概念
**思想**：一个廉价的**草稿**模型 $q$ 先提出 $\gamma$ 个 token；大的**目标**模型 $p$ 用**一次并行前向**（类似一个短的预填充）给它们全部打分，并保留与自己一致的最长前缀。验证 $\gamma$ 个 token 的代价与生成 1 个相近，因为解码受内存带宽限制。

对每个草稿 token $x \sim q$ 的**精确接受规则**（Leviathan 等；Chen 等）：
- 以概率 $\min\!\big(1, p(x)/q(x)\big)$ 接受。
- 在第一次拒绝时，丢弃其余草稿，并从**残差分布** $p'(x) \propto \max(0, p(x) - q(x))$ 中采样一个替代 token。
- 如果 $\gamma$ 个全部被接受，则在下一个位置从 $p$ 采样一个**额外（bonus）** token。
输出分布**恰好**是 $p$，而非近似：$q(x)\min(1, p/q) + P(\text{reject})\,p'(x) = p(x)$。对于贪心解码，这退化为“只要草稿 token 等于目标的 argmax 就接受”。

**速度模型**：设 $\alpha$ 为每个 token 的接受概率（假设独立同分布），$c$ 为草稿与目标每步的成本比。
- 每次目标前向的期望 token 数：$\dfrac{1 - \alpha^{\gamma+1}}{1 - \alpha}$（至少为 1）。
- 每次迭代的时间 $\propto 1 + \gamma c$，所以加速比 $= \dfrac{1-\alpha^{\gamma+1}}{(1-\alpha)(1+\gamma c)}$。
- 只有在 $\alpha$ 保持较高时增大 $\gamma$ 才有帮助；存在最优值，通常为 3-8。

**草稿来源**：
- 同一系列的较小模型（需要共用分词器）。
- **自推测**：在目标模型上增加额外的头（**Medusa**）、特征级草稿（**EAGLE**）、早退或跳层草稿。
- **提示查找 / n-gram** 草稿：从提示中复制后续内容，对摘要、代码编辑和 RAG 这类输出会重复输入的场景非常有效。

**适用场景与陷阱**：在小批量时效果最好，此时解码受内存限制。大批量时 GPU 已经受计算限制，额外的验证 FLOPs 可能抵消收益。高温度或创意文本上接受率下降；草稿模型要占用内存并有自己的 KV cache；收益取决于草稿与*目标*行为的匹配程度（微调过的目标需要重新对齐草稿）。

## 示例讲解
$p = (0.5, 0.3, 0.2)$、$q = (0.2, 0.5, 0.3)$，三个 token 的接受情况。
- 草稿 token 0：$p/q = 2.5$，以概率 1 接受。token 1：$p/q = 0.6$，以概率 0.6 接受。token 2：$p/q = 0.67$。
- 总接受质量 $\sum \min(p, q) = 0.2 + 0.3 + 0.2 = 0.7$，所以拒绝概率为 0.3。
- 残差 $\max(0, p - q) = (0.3, 0, 0)$，归一化为 $(1, 0, 0)$。
- token 0 的输出概率：$0.2 + 0.3 \cdot 1 = 0.5 = p(0)$。token 1：$0.3$。token 2：$0.2$。目标分布被精确还原。

$\alpha = 0.8$、$\gamma = 4$、$c = 0.05$（草稿每步成本为目标的 5%）时的加速比：期望 token 数 $= (1 - 0.8^5)/0.2 = 3.36$；每次迭代成本 $1 + 4 \cdot 0.05 = 1.2$；加速比 $\approx 3.36/1.2 = 2.8\times$。同样设置下若 $\alpha = 0.5$，则 $1.94/1.2 = 1.6\times$。
