## 为什么重要
语义搜索、RAG、去重和聚类都建立在同一个基本能力上：为每个句子或段落生成一个向量，其距离反映语义。面试官会问这些模型如何训练、为什么简单平均 BERT token 不够，以及检索如何上线服务。

## 概念
**句子 embedding** 把变长文本映射为一个固定大小的向量（384-1536 维），使语义相近的文本距离相近。

**朴素方案及其不足**：平均 Word2Vec 向量忽略了词序和上下文；原始 BERT 的 `[CLS]` 或平均池化向量没有为相似度训练过，在相似度任务上往往不如平均 GloVe。

**Sentence-BERT（SBERT）**：一种**双编码器**。对每个句子独立运行预训练 transformer，对 token 向量做**池化**（通常是对非 padding token 取平均；有时用 `[CLS]` 或最大池化），并在句子对上微调共享编码器（*孪生*结构）。由于每段文本只编码一次，可以预先计算并索引所有文档向量。

**训练目标**：
- 在 NLI 或 STS 标注的句子对上做**分类/回归**（早期 SBERT）。
- **带批内负例的对比学习（InfoNCE）**：对于包含 $B$ 个正例对 $(a_i, p_i)$ 的批次，其余每个 $p_j$ 都是负例：

$$\mathcal{L} = -\frac{1}{B}\sum_i \ln \frac{\exp(\text{sim}(a_i, p_i)/\tau)}{\sum_{j} \exp(\text{sim}(a_i, p_j)/\tau)}$$

  其中 $\tau$ 是温度（余弦相似度下约 0.05-0.1）。批次越大负例越多；**困难负例**（相似但错误的段落）能显著提升质量。
- 现代模型（E5、BGE、GTE、OpenAI embeddings）先在海量弱监督配对数据上预训练，再用困难负例微调。Matryoshka 训练允许截断维度。

**上线服务**：对向量做 L2 归一化，使点积等于余弦相似度，存入向量索引（精确检索，或 HNSW、IVF 等近似最近邻），取 top-$k$。**双编码器 vs 交叉编码器**：交叉编码器把查询和文档一起读入，更准确但无法预先计算。标准流程是双编码器检索约 100 个候选，再用交叉编码器重排。

**陷阱**：查询和文档要使用同一个模型和相同的前缀约定（`query:` / `passage:`）；非对称搜索（短查询 vs 长段落）不同于对称相似度；领域偏移会损害效果，所以要在自己的数据上评估（recall@k、MRR、nDCG）；不同模型的 embedding 不可比较。

## 示例讲解
带 padding 掩码的平均池化。token 向量 $[1,2]$、$[3,4]$ 以及一个 pad $[9,9]$，掩码为 $[1,1,0]$：对真实 token 取平均得 $([1,2]+[3,4])/2 = [2,3]$。如果把 pad 也算进去会得到 $[4.33, 5]$，显然是错误的。

批内 InfoNCE，$B = 2$，余弦相似度 $\begin{pmatrix}0.8 & 0.2 \\ 0.1 & 0.6\end{pmatrix}$（行：锚点，列：候选，对角线 = 正例），$\tau = 0.5$。第 1 行 logits $[1.6, 0.4]$：损失 $= \ln(1 + e^{-1.2}) = 0.263$。第 2 行 logits $[0.2, 1.2]$：损失 $= \ln(1 + e^{-1.0}) = 0.313$。平均 $= 0.288$。

```quiz
  "explanation": "交叉编码器很准确，但每个文本对需要一次前向计算。应先用带索引的双编码器获取候选，再对前几名重排。"

```

```quiz

  "id": "q2",
```


> [!TIP] 面试技巧
> - 画出双编码器（离线索引，快）与交叉编码器（重排，准）的流程，并说明为何两者都用。
