## 为什么重要
几乎所有现代 LLM（GPT、Llama、Claude、Gemini、Mistral）都是仅解码器的 Transformer。面试官会问：它如何训练、因果掩码为何重要，以及为什么这种设计胜过编码器-解码器。

## 概念
仅解码器模型是一堆使用**因果自注意力**（token $t$ 只关注 $\le t$ 的 token）且没有交叉注意力的 Transformer 层。

- **目标**：自回归地建模序列，$p(x) = \prod_t p(x_t \mid x_{<t})$。损失是预测每个下一个 token 的平均交叉熵。
- **教师强制（teacher forcing）**：训练时输入真实前缀，因此对 $n$ 个 token 的一次前向传播并行得到 $n$ 个损失。生成则是串行的：每个新 token 一次前向传播（**KV 缓存**使其更便宜）。
- **因果掩码**：下三角矩阵，在 softmax 之前把对角线以上的分数设为 $-\infty$。它防止模型通过读取答案来“作弊”。
- **困惑度** $= \exp(\text{每个 token 的平均 NLL})$，即有效分支因子；越低越好，且只有在相同分词器下才可比较。
- **输出头**：最终隐藏状态 $\to$ 词表上的线性层（常与输入嵌入共享权重）$\to$ softmax。
- **上下文学习**：规模足够大时，模型无需更新权重就能遵循提示中的指令和示例。基础模型 = 预训练的下一个 token 预测器；对话模型 = 基础模型加指令微调和 RLHF。
- **为什么仅解码器胜出**：在无标注文本上只用一个简单目标，每个 token 都提供信号，同一个堆栈把所有任务都当作文本续写，KV 缓存让服务更高效。在相同算力下编码器-解码器可以达到类似效果，但对开放式对话不太方便。
- **局限**：每个位置只能看到左侧上下文（单从参数效率看，纯分类任务弱于双向编码器），可能产生幻觉，注意力开销随上下文增长。

## 示例讲解
某模型对一个句子的四个真实下一 token 给出的概率为 $0.5, 0.25, 0.5, 0.125$。

以比特计的 NLL：$1 + 2 + 1 + 3 = 7$，均值 $= 7/4 = 1.75$ 比特每 token。困惑度 $= 2^{1.75} \approx 3.36$：相当于每一步在约 3.4 个 token 中均匀选择的不确定性。（以 nat 计：$\exp(\text{mean } -\ln p)$ 得到相同的值。）

对于 4 个 token 的输入，因果掩码为 $\begin{pmatrix}1&0&0&0\\1&1&0&0\\1&1&1&0\\1&1&1&1\end{pmatrix}$，所以第 2 行只混合 token 0、1、2。

> [!TIP] 面试技巧
> - 讲清训练（并行、教师强制）与推理（串行、KV 缓存）的区别；这种不对称是面试常问点。
> - 知道因果掩码使目标成立；没有它，模型可以直接复制下一个 token。
> - 说明为什么仅解码器占主导：简单且可扩展的目标、上下文学习，以及用一种架构处理所有任务。
