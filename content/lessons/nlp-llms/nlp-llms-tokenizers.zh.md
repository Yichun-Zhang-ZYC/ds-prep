## 为什么重要
分词决定序列长度、词表大小、每次请求的成本，以及模型如何处理罕见词、数字和其他语言。面试官会问：BPE 如何训练、WordPiece 有何不同，以及为什么子词优于词或字符。

## 概念
**为什么用子词**：词级词表会爆炸并遇到未登录词（OOV）；字符级序列又太长。子词分词器把高频词保持完整，把罕见词拆成片段，因此不会有 OOV，序列也保持较短。

**BPE（字节对编码）**（GPT-2/3/4、Llama、RoBERTa）
1. 预分词成单词（按空白/正则切分）并计数；以字符（或字节）作为初始词表。
2. 反复找出**出现次数最多的相邻对**并合并为新符号；记录该合并。
3. 达到目标词表大小（如 32k-200k）时停止。
4. **编码**：把单词拆成字符，然后按学习到的顺序依次应用合并。
- **字节级 BPE** 从 256 个字节开始，因此任何 Unicode 文本都可表示，不需要未知 token。

**WordPiece**（BERT、DistilBERT）
- 同样的循环，但合并分数为 $\dfrac{\text{count}(ab)}{\text{count}(a)\,\text{count}(b)}$（似然增益），偏向其组成部分很少单独出现的对。
- 延续片段带 `##` 前缀：`unhappiness` $\to$ `un ##happi ##ness`。编码使用贪心的**最长匹配优先**。

**Unigram / SentencePiece**（T5、Llama 1/2）：从很大的词表开始，按似然损失剪枝；SentencePiece 把空白当作符号（`▁`），因此与语言无关。

**实际影响**
- 词表更大：序列更短，但嵌入矩阵更大，罕见 token 的行更稀疏。
- 分词决定成本和上下文上限：大约 1 个 token $\approx$ 4 个英文字符或 0.75 个单词；其他语言和代码通常需要更多 token。
- 典型的失败模式：算术和拼写较差（数字被不一致地切分）、故障 token、对空白敏感。分词器在预训练后就固定了；更换它意味着重新训练或嵌入迁移。

## 示例讲解
语料词频：`hug`:10、`pug`:5、`pun`:12、`bun`:4、`hugs`:5。

相邻对计数：`(u,g)` = 10+5+5 = 20，`(p,u)` = 5+12 = 17，`(u,n)` = 12+4 = 16，`(h,u)` = 15，`(g,s)` = 5，`(b,u)` = 4。

- 合并 1：`u g` $\to$ `ug`（20）。现在 `(u,n)`=16，`(h,ug)`=15，`(p,u)`=12。
- 合并 2：`u n` $\to$ `un`（16）。现在 `(h,ug)`=15，`(p,un)`=12。
- 合并 3：`h ug` $\to$ `hug`（15）。

`hugs` 编码为 `hug` + `s`；`bug` 编码为 `b` + `ug`。在同一语料上，WordPiece 会先合并 `(g,s)`：分数 $5/(20 \cdot 5) = 0.05$，而 `(u,g)` 为 $20/(36 \cdot 20) \approx 0.028$。

> [!TIP] 面试技巧
> - 用一句话描述 BPE：从字符/字节开始，贪心地合并最频繁的相邻对，直到词表填满。
> - 说明 WordPiece 的不同之处（基于似然的分数、`##` 前缀、最长匹配编码），以及字节级 BPE 没有未知 token。
> - 把分词与成本、上下文长度和失败模式（数字、非英文文本）联系起来。
