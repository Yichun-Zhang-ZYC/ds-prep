## 为什么重要
每次模型发布都会引用基准分数，每个 ML 团队也都要判断某个模型在自己的任务上是否真的更好。面试官希望看到你了解标准基准衡量什么、pass@k 和 Elo 等指标如何计算，以及分数为何容易被虚高或误读（见“幻觉”和“微调、提示与 RAG 的选择”）。

## 概念
**基准类别**
- **知识 / 推理（选择题）**：MMLU（57 个学科；顶尖模型已接近饱和，因此有更难的 MMLU-Pro 和 GPQA）、ARC、HellaSwag。
- **数学**：GSM8K（小学应用题，已饱和）、MATH、AIME 类题集。按最终答案精确匹配评分。
- **代码**：HumanEval 和 MBPP（函数合成，单元测试；已饱和）、LiveCodeBench（新题）、SWE-bench Verified（在代码库里解决真实的 GitHub issue）。
- **指令遵循**：IFEval（可验证的约束）。
- **开放式 / 对话**：MT-Bench、AlpacaEval、Arena-Hard（LLM 当评委）和 Chatbot Arena（人类两两投票，用 Bradley-Terry / Elo 排序）。
- `lm-evaluation-harness` 和 HELM 等评测框架规范了提示和评分方式。

**关键指标**
- **pass@k**：$k$ 个样本中至少有一个正确的概率。给定 $n$ 个样本、其中 $c$ 个正确，无偏估计量为 $1 - \binom{n-c}{k} / \binom{n}{k}$。$n$ 较小时不要用 $1-(1-c/n)^k$ 估计（有偏）。
- **Elo / Bradley-Terry**：$P(A \text{ 战胜 } B) = 1/(1 + 10^{(R_B - R_A)/400})$；更新 $R_A \leftarrow R_A + K\,(S - E_A)$。
- **置信区间**：对 $n$ 道题上的准确率 $\hat p$，标准误为 $\sqrt{\hat p(1-\hat p)/n}$。在 500 题的基准上提升 1 个点通常只是噪声。应在相同题目上用**配对**检验来比较模型。

**常见陷阱**
- **数据污染**：测试题泄漏进预训练数据（用 n-gram 重叠检查、canary 字符串、新鲜或私有的保留集、动态基准来应对）。
- **饱和与古德哈特定律**：基准一旦被针对性优化，分数就不再反映真实能力。
- **提示与格式敏感性**：few-shot 数量、答案抽取方式、选项顺序和聊天模板都可能让分数变化好几个点。要报告完整设置。
- **LLM 评委的偏差**：位置偏差、冗长偏差、自我偏好。可通过交换顺序、控制长度的胜率、评分细则，以及与人工标注校准来缓解。
- **基准不等于你的任务**：用真实流量构建小型的任务专属评测集，提示带版本管理，并做回归测试。
- 报告不同随机种子和采样设置下的方差；在相同推理算力下比较（推理模型可能靠“想得更久”获胜）。

## 示例讲解
**pass@k**：模型在 $n = 10$ 个样本中有 $c = 3$ 个解对了题目。pass@1 $= 0.3$。pass@5 $= 1 - \binom{7}{5}/\binom{10}{5} = 1 - 21/252 = 0.917$。

**Elo**：A（1000）战胜 B（1200）。A 的期望胜率为 $1/(1 + 10^{200/400}) = 0.240$。取 $K = 32$，A 增加 $32 \times (1 - 0.240) = 24.3$ 分，B 减少同样的分数。爆冷使评分变化远大于符合预期的结果。

**提升是真的吗？**模型 B 在 $n = 1000$ 题上得分 82%，模型 A 为 81%。单个准确率的标准误为 $\sqrt{0.8 \cdot 0.2/1000} = 1.26$ 个点，所以 95% 区间约为 $\pm 2.5$ 个点。除非对逐题结果做的配对检验另有显示，否则 1 个点的差异在噪声范围之内。

> [!TIP] 面试技巧
> - 不要只复述分数：先说明基准衡量什么、是否已饱和、是否可能被污染。
> - 会计算 pass@k、Elo 更新和准确率的标准误，并解释为什么小差距可能只是噪声。
> - 谈到 LLM 评委时，提到位置、冗长、自我偏好偏差及其缓解方法，并强调要建立任务专属的评测集。
