## 为什么重要
百万 token 的上下文到处被宣传，但接受 128k token 的模型并不等于能很好地利用它们。面试官会考察上下文是如何扩展的（RoPE 缩放）、代价是什么，以及检索质量为何下降（见“位置编码”“FlashAttention”和“上下文窗口与 KV cache”）。

## 概念
**三个独立的问题**：(1) 模型必须表示从未训练过的位置；(2) 计算和内存必须装得下；(3) 模型必须真正*用上*远处的信息。

**1. 扩展位置（基于 RoPE 的模型）**
- **位置插值（PI）**：把位置按 $L_{train}/L_{target}$ 缩放，使所有角度保持在训练范围内。简单，需要短时间微调，但会把相邻 token 挤在一起，模糊局部细节。
- **NTK 感知缩放**：提高 RoPE 基数，对缩放倍数 $s$ 取 $b' = b \cdot s^{d/(d-2)}$。高频维度（局部细节）几乎不变，低频维度被插值。
- **YaRN**：按频率分别插值（高频不动、低频插值、中间平滑过渡），再加上注意力温度校正。只需少量微调就能达到较大的扩展倍数。
- **在长文档上继续预训练**（以及长上下文 SFT 混合数据）才是真正起作用的部分；缩放只提供一个好的初始化。始终保留一些短数据以避免性能退化。

**2. 计算和内存**
- 注意力的 FLOPs 是 $O(n^2)$；FlashAttention 解决内存而非 FLOPs。**KV cache** 线性增长：每个 token $2 \cdot L \cdot H_{kv} \cdot d_h \cdot b$ 字节（见“上下文窗口与 KV cache”）。GQA/MLA、KV 量化和淘汰策略有帮助。
- **滑动窗口注意力**为每层保持固定大小的缓存；信息仍可跨层传播（有效感受野 $\approx$ 层数 $\times$ 窗口）。
- **注意力汇聚点（attention sinks）**（StreamingLLM）：最前面的几个 token 吸收多余的注意力质量；淘汰它们会破坏模型。保留汇聚点加最近窗口可以无限流式生成，但会*遗忘*中间内容。
- **上下文并行 / Ring attention**：把序列分片到多块 GPU，并循环传递 K/V 块，使单个请求可以超过单卡内存。
- **前缀缓存**和**提示压缩**可以降低重复成本。

**3. 利用上下文**
- **中间丢失（lost in the middle）**：位于提示开头和结尾的事实准确率通常最高，中间最低。
- 不要只用单针检索来评估：还要做多针、聚合和多跳任务（RULER、LongBench、HELMET）。**有效**上下文长度往往远短于**宣称**的长度。
- **RAG 与长上下文**：长上下文更简单，并支持跨文档推理；RAG 每次查询更便宜，可超出任何窗口，并能给出引用。许多系统会两者结合。

**常见陷阱**：只报最大上下文而不报延迟（预填充随长度二次增长）；以为光靠缩放就够了；忘记除非缓存前缀，否则每一轮对话都要按 token 付费。

## 示例讲解
把训练长度 4k 的模型扩展到 32k：缩放倍数 $s = 8$。

**位置插值**：位置 20,000 变为 $20000/8 = 2500$，落在训练范围内。代价：相邻 token 现在只相差 $1/8$ 个位置步长，细微的局部区分被压缩。

**NTK 感知**，$d = 128$：$b' = 10000 \cdot 8^{128/126} \approx 82{,}685$。最快的一对（$\theta_0 = 1$）不变，而最慢的波长增大约 $8.3\times$，因此长距离可以容纳，同时保留局部分辨率。

**滑动窗口 + 1 个汇聚点**，窗口 3，序列长度 6：第 5 个 token（从 0 开始）关注 $\{0, 3, 4, 5\}$：汇聚点 0 加最近 3 个 token。第 1 个 token 关注 $\{0, 1\}$。

KV 成本：类似 Llama-3-8B 的模型（32 层、8 个 KV 头、头维度 128、fp16）每个 token 需要 128 KiB，所以单个请求的 128k 提示就占用 16 GiB 的 KV cache。
