## 为什么重要
不看执行计划的优化就是在猜。面试高级分析师和数据工程师岗位时，面试官会期望你读懂执行计划，并指出代价最高的部分。

## 概念
`EXPLAIN` 展示数据库打算如何执行查询；`EXPLAIN ANALYZE`（Postgres）会真正执行并报告实际耗时和行数。数仓用可视化的“查询剖析”（query profile）展示同样的信息。

需要关注的内容：

| 计划节点 | 含义 | 什么时候是危险信号 |
|---|---|---|
| Seq Scan / 全表扫描 | 读取每一行 | 表很大且过滤条件区分度高 |
| Index Scan / Index Seek | 使用索引 | 过滤条件区分度高时理应出现 |
| Hash Join | 对一侧建哈希表 | 用来建表的那一侧非常大 |
| Nested Loop | 对 A 的每一行去探查 B | 两侧都很大（一侧很小时没问题） |
| Sort | 排序 | 大排序溢出到磁盘 |
| 估计行数 vs 实际行数 | 优化器的估计与实际 | 相差 10 倍以上：统计信息过期 |

在数仓里还要看**扫描的字节数**（决定费用），以及节点之间的 **shuffle / 数据倾斜**。

## 示例讲解
一个带过滤的连接在 Postgres 中的执行计划（简化）：

```text
Hash Join  (cost=..  rows=1200)  (actual rows=980)
  Hash Cond: (o.customer_id = c.id)
  -> Seq Scan on orders o  (rows=5,000,000)
       Filter: (order_date >= '2024-06-01')
       Rows Removed by Filter: 4,900,000
  -> Hash  -> Seq Scan on customers c
```

解读：数据库扫描了全部 500 万条订单，只为保留其中 10 万条。在 `order_date` 上加索引（或分区），就可以只读最近的数据。

> [!TIP] 面试技巧
> - 指出你要优化的具体节点（“按日期过滤 orders 的那个全表扫描”）。
> - 提一句 `EXPLAIN ANALYZE` 会真正执行查询；不要在生产环境对昂贵的 `DELETE` 这样做。
> - 在 BigQuery 或 Snowflake 里，先谈扫描字节数、分区裁剪和数据倾斜。
