## 为什么重要
每个可扩展的服务前面都有负载均衡器或反向代理，模型服务端点也不例外。面试官会问流量如何分发、如何检测故障，以及 L4 与 L7 有何区别。

## 概念
**反向代理**接收客户端请求并转发给后端服务器，客户端看不到后端。**负载均衡器（LB）**是以在多个后端之间分摊负载为主要职责的反向代理。常见的有 Nginx、HAProxy、Envoy、AWS ALB/NLB 和 GCP Cloud Load Balancing。

**L4 与 L7**：
- **L4（传输层）**：按 IP 和端口转发 TCP/UDP 连接，不读取负载内容。速度很快，与协议无关（AWS NLB）。
- **L7（应用层）**：理解 HTTP，因此可以按主机名、路径或请求头路由，终止 TLS，重写、缓存、压缩，并做金丝雀分流（AWS ALB、Nginx、Envoy）。

**算法**：
- **轮询 / 加权轮询**：依次轮流选择后端；权重让更强的机器承担更多。
- **最少连接**：选择活跃连接最少的后端；请求耗时差异大时更合适。
- **IP / 一致性哈希**：同一客户端或键映射到同一后端（会话亲和、缓存局部性）；一致性哈希在后端变化时能限制重新映射的范围。

**健康检查**会摘除不健康的后端：*主动*（LB 每隔几秒探测 `/healthz`）和*被动*（LB 剔除返回错误的后端）。要区分**存活探针**（重启我）与**就绪探针**（可以给我流量）。

**其他职责**：TLS 终止、发布时的连接排空、限流，以及用 `X-Forwarded-For` 传递客户端 IP。优先使用**无状态**服务；粘性会话会损害均衡和故障转移。LB 本身也不能成为单点故障（多节点、前置 anycast 或 DNS）。

```nginx
upstream api {
    least_conn;
    server 10.0.1.10:8000 max_fails=3 fail_timeout=10s;
    server 10.0.1.11:8000;
}
server {
    listen 443 ssl;
    location /api/ { proxy_pass http://api; }
}
```

## 示例讲解
三个后端 A、B、C 提供模型 API。使用轮询时，9 个请求依次为 A、B、C、A、B、C、A、B、C，每台 3 个。现在 B 的健康检查失败，接下来 6 个请求只在 A 和 C 之间轮转，各 3 个，存活服务器各自的流量占比从 33% 升到 50%。如果每台服务器按 3 台时 40% 的利用率配置容量，现在就是 60%，所以要预留 **N+1** 的余量。使用最少连接时，如果一个慢请求让 A 持有 5 个连接而 C 只有 1 个，新请求会流向 C，直到连接数接近。

> [!TIP] 面试技巧
> - 说清 L4 与 L7 各自能依据什么路由，并举出具体工具（ALB、Nginx、Envoy）。
> - 解释健康检查、连接排空和 N+1 容量，避免一个节点故障引发级联。
> - 陷阱：粘性会话和内存中的状态；把状态放到 Redis 或数据库，让任意后端都能处理任意请求。
