## 为什么重要
哈希表把“我以前见过这个吗？”和“这样的有多少个？”变成 $O(1)$ 的查询，所以它是把 $O(n^2)$ 暴力解降到 $O(n)$ 的首选工具，出现在大量面试题中。

## 概念
**哈希表**（`dict`）存储键 → 值的映射；**哈希集合**（`set`）只存储键。插入、删除和查找**平均**为 $O(1)$，最坏情况（大量冲突）为 $O(n)$。键必须可哈希且不可变：整数、字符串、元组可以；列表和字典不行（改用 `tuple(...)` 或 `frozenset`）。

常见模式：
- **存在性 / 去重**：加入前先判断 `if x in seen`。在列表里判断成员是 $O(n)$，在集合里是 $O(1)$。
- **补数查找**：要找满足 $a + b = k$ 的数对，保存已经见过的值并查找 $k - a$（Two Sum）。
- **频次统计**：用 `Counter(s)` 处理字母异位词、多数元素、前 k 个高频元素。
- **按规范键分组**：用 `tuple(sorted(word))` 把字母异位词分组。
- **前缀和 + 哈希表**：以 $j$ 结尾且和为 $k$ 的子数组存在，当且仅当 $\text{prefix}_j - k$ 作为之前的前缀和出现过。保存 前缀和 → 次数。
- **索引映射**：值 → 最后出现的下标，用于“最近的相同元素”或窗口类问题。

复杂度：通常时间 $O(n)$、额外空间 $O(n)$；是用内存换速度。Python 的 dict 保持插入顺序（3.7+）。用 `dict.get(k, 0)`、`defaultdict` 或 `Counter` 避免 KeyError。

## 示例讲解
**和为 k 的子数组**，`nums = [1, 2, 3]`，`k = 3`。用 `count[prefix]` 记录到目前为止见过的前缀和，初始为 `{0: 1}`（空前缀）。处理每个元素时，把 `count[prefix - k]` 加到答案里。

```text
x=1: prefix=1, need prefix-k = -2  -> not seen, ans=0.  count={0:1, 1:1}
x=2: prefix=3, need 0              -> seen once, ans=1 ([1,2]). count={0:1, 1:1, 3:1}
x=3: prefix=6, need 3              -> seen once, ans=2 ([3]).   count={0:1, 1:1, 3:1, 6:1}
```

答案是 2，一次遍历完成：时间 $O(n)$、空间 $O(n)$，而检查所有子数组需要 $O(n^2)$。初始的 `{0: 1}` 使得从下标 0 开始的子数组也能被统计。这里不能用滑动窗口，因为数字可能为负。

> [!TIP] 面试技巧
> - 说明复杂度上的取舍：哈希表用 $O(n)$ 额外内存换取平均 $O(1)$ 的查询。
> - 陷阱：把列表当作 dict 的键（不可哈希）；先转换成元组。
> - 陷阱：前缀和计数时，忘记用 `{0: 1}` 初始化，或者在查询之前就先更新了哈希表。
> - 追问：“数据放不进内存怎么办？”可以谈排序加双指针，或按哈希值分区。
