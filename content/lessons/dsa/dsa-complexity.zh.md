## 为什么重要
每道编程面试题的结尾几乎都是“时间和空间复杂度是多少？”。能直接从代码读出复杂度，并说明输入放大 10 倍或 1000 倍时运行时间如何变化，是所有其他数据结构与算法主题的基础能力。

## 概念
**Big-O** 描述基本操作步数（或内存单元数）如何随输入规模 $n$ 增长，忽略常数和低阶项。$O(f(n))$ 是增长的上界；除非面试官说明是平均或均摊，否则通常指**最坏情况**。

常见复杂度类别，增长由慢到快：
- $O(1)$：哈希查找、数组下标访问、栈的 push/pop。
- $O(\log n)$：二分查找、平衡树查找、堆的 push/pop、每步把问题减半。
- $O(n)$：遍历一遍输入。
- $O(n \log n)$：高效排序、带线性合并的分治。
- $O(n^2)$：对输入做嵌套循环、枚举所有数对。
- $O(2^n)$：枚举所有子集、朴素递归斐波那契；$O(n!)$：枚举所有排列。

**经验法则**：
- 顺序执行的代码块相加，嵌套的相乘：$O(a) + O(b) = O(a + b)$，循环里套循环是 $O(a \cdot b)$。输入不同时用不同字母（$n$ 和 $m$）。
- 去掉常数：$O(2n + 5) = O(n)$。保留主导项：$O(n^2 + n) = O(n^2)$。
- 变量每次减半或翻倍的循环是 $O(\log n)$。
- 递归：（调用次数）×（每次调用的工作量）。递归深度也会占用栈空间。
- **空间**统计输入之外的额外内存：新建大小为 $n$ 的列表是 $O(n)$，几个变量是 $O(1)$，递归深度 $d$ 是 $O(d)$。
- **均摊**成本是对一个操作序列取平均：向动态数组 append 是均摊 $O(1)$，尽管偶尔扩容要花 $O(n)$。
- 在循环里写字符串 `s += c` 在很多语言里是 $O(n^2)$，因为每次拼接都要复制；应改为构建列表再 `"".join`。

粗略的预算：约 $10^8$ 次简单操作可以在几秒内完成，所以 $n = 10^5$ 需要 $O(n \log n)$ 或更优，而 $n = 20$ 允许 $O(2^n)$。

## 示例讲解
分析下面的代码：

```python
def f(arr):
    n = len(arr)
    total = 0
    for x in arr:                # n iterations
        total += x
    i = 1
    while i < n:                 # i = 1, 2, 4, ... doubles each time
        total += arr[i]
        i *= 2
    for i in range(n):           # n * n iterations
        for j in range(n):
            if arr[i] == arr[j]:
                total += 1
    return total
```

取 $n = 8$ 来追踪：第一个循环执行 8 次；while 循环中 $i = 1, 2, 4$，到 8 时停止，共 3 步（$\log_2 8$）；嵌套循环执行 $8 \times 8 = 64$ 次。总计 $8 + 3 + 64 = 75$。一般情况是 $n + \log n + n^2$，主导项给出时间复杂度 $O(n^2)$。额外空间只有几个标量，所以是 $O(1)$。

把 $n$ 翻倍到 16 得到 $16 + 4 + 256 = 276$，工作量接近 4 倍：这个比例正是平方级算法的特征。

> [!TIP] 面试技巧
> - 始终同时说明时间和空间复杂度，并指明是哪种情况（最坏、平均、均摊）。
> - 有多个输入时说明 $n$ 指什么：两个数组用 `O(n + m)`，网格用 `O(rows * cols)`。
> - 陷阱：忽略隐藏成本，例如 `list.insert(0, x)`、`x in list`、切片，以及循环里的 `sorted()`。
> - 如果你的第一个想法是 $O(n^2)$，要先说出来，再说明用什么数据结构（哈希表、排序、双指针）可以降下来；这正是面试官想听到的。
