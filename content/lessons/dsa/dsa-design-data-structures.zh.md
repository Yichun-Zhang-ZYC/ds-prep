## 为什么重要
“设计一个数据结构”类问题考察你能否组合基础组件（哈希表、双向链表、栈、堆）来满足严格的时间界限，以及能否写出整洁且处理好边界情况的类代码。LRU 缓存是大型科技公司最常问的题目之一；最小栈和迭代器是快速热身题。

## 概念
**方法。**（1）写出 API 和要求的复杂度（例如 `get` 与 `put` 均为 $O(1)$）。（2）问每个基础组件让哪个操作变得便宜，然后组合它们。（3）说明类维护的不变式。（4）编码，然后测试边界（容量为 1、空、重复键）。

**LRU 缓存**（`get`、`put` 为 $O(1)$，满时淘汰最近最少使用的项）。
- **哈希表**提供 $O(1)$ 的键到节点查找，但没有顺序。
- **双向链表**维护使用时间顺序，并且**已知节点指针时可在 $O(1)$ 内删除该节点**（单链表做不到，普通列表需要 $O(n)$）。
- 组合：`map: key -> node`；链表头 = 最近使用，尾 = 最久未使用。`get` 把节点移到头部。`put` 更新并移动，或者插入头部，若超出容量则删除尾节点及其 map 条目。使用**哨兵**头尾节点来避免空指针检查。
- 在 Python 中，`collections.OrderedDict` 配合 `move_to_end` 和 `popitem(last=False)` 效果相同；可以提一下，但要准备好手写链表。

**最小栈**（`push`、`pop`、`top`、`get_min` 均为 $O(1)$）：随每个元素保存**该深度处的最小值**（元组 `(value, min_so_far)`），或者另用一个最小值栈。弹出时自动恢复上一个最小值。同样的技巧适用于最大栈。

**用两个栈实现队列**：压入 `in`；当 `out` 为空且需要弹出/查看队首时，把 `in` 全部倒入 `out`。每个元素最多移动两次，均摊 $O(1)$。

**迭代器**（展平嵌套列表、BST 中序、zip/peek）：在显式栈上保存**惰性状态**，而不是一次性物化所有元素。`has_next` 应负责推进到下一个真正的值，这样 `next` 就很简单，并且可以重复调用 `has_next` 而无副作用。内存为 $O(\text{depth})$，而不是 $O(n)$。

**其他需要了解的**：LFU 缓存（频率桶，$O(1)$）、随机化集合（列表 + 映射，用交换删除使 `get_random` 为 $O(1)$）、带时间戳的键值存储（对时间戳二分）、点击计数器（队列或分桶）。

**陷阱。** 淘汰时忘记更新 map。更新已有键时没有刷新使用时间。容量边界的差一错误（插入后当 `len > capacity` 时淘汰）。`has_next` 消耗了元素。

## 示例讲解
**LRU 缓存，容量 2。** 列表按最近使用在前显示。

```text
put(1,1)   [1]
put(2,2)   [2,1]
get(1)=1   [1,2]            1 moved to head
put(3,3)   [3,1]            full: evict tail 2
get(2)=-1  [3,1]            miss
put(4,4)   [4,3]            full: evict tail 1
get(1)=-1  [4,3]            miss
get(3)=3   [3,4]
get(4)=4   [4,3]
```

每一步只触及常数个指针：$O(1)$。

**最小栈。** 依次压入 -2、0、-3，保存 `(value, min)`：`(-2,-2)`、`(0,-2)`、`(-3,-3)`。`get_min()` = -3。`pop()` 删除 `(-3,-3)`。`top()` = 0，`get_min()` 又变回 -2，无需任何扫描。

> [!TIP] 面试技巧
> - 先澄清 API 和要求的复杂度，再说出每个数据结构及其存在的理由。
> - 在链表中使用哨兵节点；它能消除大部分边界情况。
> - 提到 `OrderedDict` 是生产环境的捷径，但如果被问到原理，要能实现链表。
> - 测试：容量为 1、更新已有键（刷新使用时间）、对缺失键调用 get，以及连续两次调用 `has_next`。
