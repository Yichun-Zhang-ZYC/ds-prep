---

## 为什么重要
用户 ID、邮编、商品 SKU、URL 和商户名称可能有数百万种取值。对它们做独热编码要么不可行，要么会过拟合，所以面试官会问你打算怎么做。

## 概念
问题：巨大的稀疏矩阵、行数太少无法学习的稀有类别、预测时出现的未见类别，以及树模型会通过孤立单个类别而过拟合。

可选方案，大致从最简单到最强大：
1. **合并稀有类别**：保留前 N 个或行数 ≥ m 的类别；其余映射为 “Other”。生产环境中的未见值也这样处理。
2. **频率 / 计数编码**：类别的热门程度本身往往就有预测力。
3. **目标编码**，配合**平滑**和**折外**计算（见编码那一课）。
4. **哈希技巧**：用哈希函数映射到固定数量的桶。内存恒定，能处理新值；冲突会带来一些噪声。
5. **层级 / 领域特征**：邮编 → 城市、州、收入中位数；URL → 域名；SKU → 类目、品牌、价格段。
6. **学习得到的嵌入**：在神经网络中训练的稠密向量（或通过矩阵分解 / word2vec 式的共现学习）。推荐系统中用户和物品的标准做法。
7. **原生支持**：CatBoost（有序目标统计）、LightGBM 的类别划分（配合 `min_data_per_group` 之类的正则化）。

还要问这个特征到底该不该用：原始用户 ID 会让模型记住用户，在新用户上失效；聚合的行为特征通常泛化得更好。

## 示例讲解
欺诈模型中有 40 万种取值的商户 ID：保留交易数 ≥ 100 的商户（8 千个），其余映射为 “rare”。再加上每个商户折外计算并平滑的欺诈率、商户交易数，以及商户类别码（约 500 种取值，用独热或目标编码）。验证集 PR-AUC 提升了，而且新商户仍然能通过类别和计数得到合理的特征。
