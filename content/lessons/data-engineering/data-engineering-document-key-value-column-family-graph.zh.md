## 为什么重要
“NoSQL”涵盖了差异很大的各类系统。面试官期望你能把每一类与合适的用例对应起来，并了解它们的主要权衡。

## 概念
| 家族 | 数据模型 | 例子 | 优势 | 典型用途 |
|---|---|---|---|---|
| **键值** | 键 → 不透明的值 | Redis、DynamoDB、Memcached | 按键查找极快、简单、可水平扩展；Redis 还提供 TTL 和多种数据结构 | 缓存、会话、购物车、限流、特征服务 |
| **文档** | 键 → 类 JSON 文档（可嵌套） | MongoDB、Couchbase、Firestore | 模式灵活、嵌套对象与应用对象一致、支持二级索引 | 商品目录、用户资料、内容 |
| **宽列（列族）** | 行键 → 按列族分组的许多列；按键排序 | Cassandra、HBase、Bigtable、ScyllaDB | 写入吞吐量极大、按分区键组织时间序列、多区域部署 | IoT、事件日志、消息、时间序列 |
| **图** | 带属性的节点 + 关系 | Neo4j、Amazon Neptune、TigerGraph | 多跳遍历很快 | 社交网络、欺诈团伙、推荐、知识图谱 |

设计要点：
- **键值 / 宽列**：围绕查询建模；选择能分散负载（避免热点分区）并支持你的访问模式的分区键。Cassandra 的查询必须包含分区键；为每个查询反规范化出一张表。
- **文档**：把一起读取的数据嵌入在一起；对被广泛共享的数据使用引用。注意无限增长的数组和跨文档的一致性。
- **图**：像“买过 X 的朋友的朋友”这样的遍历只需几跳，而不是大量的自连接。查询语言：**Cypher**（Neo4j）、Gremlin、GQL。分析算法：PageRank、社区发现、最短路径。
- **向量数据库**（Pinecone、Weaviate、pgvector）是用于嵌入相似度搜索的新兴家族。

## 示例讲解
欺诈检测：把账户、设备、银行卡和地址作为节点；“使用了”“共享地址”作为边。Cypher：
```
MATCH (a:Account {id: $id})-[:USED]->(d:Device)<-[:USED]-(other:Account)
WHERE other.flagged = true
RETURN other.id
```
在图数据库中，找出 2–3 跳之内与被标记账户相关联的账户是一个实时查询，而在 SQL 中则需要代价高昂的递归连接。

> [!TIP] 面试技巧
> - 把每个家族对应到一个用例：键值（缓存/会话）、文档（灵活的实体）、宽列（海量时间序列写入）、图（关系）。
> - 谈宽列/键值时讨论分区键和热点分区；谈文档时讨论嵌入与引用。
> - 谈图数据库时提到 Cypher 和多跳遍历，谈嵌入时提到向量数据库。
