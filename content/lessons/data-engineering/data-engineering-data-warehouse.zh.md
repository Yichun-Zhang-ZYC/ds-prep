## 为什么重要
云数据仓库是大多数分析技术栈的核心。面试官会问 Snowflake、BigQuery 和 Redshift 底层是如何工作的、如何计费，以及如何让查询又快又省钱。

## 概念
**数据仓库**是一个集中式、结构化、可用 SQL 查询的存储，存放经过清洗、整合的历史数据，用于分析。

现代云数据仓库有共同的设计：
- **列式存储**并配合压缩；数据被切分成带有最小/最大值元数据的微分区/数据块，用于**剪枝**。
- **存储与计算分离**：数据存放在便宜的对象存储中；计算集群独立扩缩容（并且可以暂停）。
- **MPP**（大规模并行处理）：一个查询被拆分到许多工作节点上执行。

| | Snowflake | BigQuery | Redshift |
|---|---|---|---|
| 计算 | 虚拟仓库（可选规格，自动挂起） | 无服务器的 slot | 预置集群或 Serverless |
| 计费 | 按仓库运行秒数计 credit + 存储 | 按需按扫描的 TB 计费，或预留 slot | 节点小时（或 RPU 小时）+ 存储 |
| 调优手段 | 聚簇键、仓库规格、结果缓存 | 分区、聚簇、避免 SELECT * | 排序键、分布键、VACUUM/ANALYZE |
| 额外功能 | 零拷贝克隆、时间旅行、数据共享 | 嵌套/重复字段、BI Engine、SQL 中的 ML | 与 AWS 紧密集成，用 Spectrum 查询 S3 |

成本与速度方面的习惯：
- 只选需要的列（列式存储：成本 ∝ 读取的列）。避免 `SELECT *`。
- 在分区/聚簇列上筛选，让引擎能剪枝数据块。
- 用增量模型 / 物化视图为仪表盘预聚合。
- 警惕连接导致的行数爆炸，以及反复的全表重建。

数据仓库内部的分层（常见约定）：**原始/暂存层 → 中间层 → 数据集市层**（维度模型），通常用 dbt 构建。

## 示例讲解
一张 10 TB 的 BigQuery 事件表，按 `event_date` 分区，按 `user_id` 聚簇。`SELECT * FROM events` 扫描 10 TB（按需价格 \$6.25/TB，约 \$62）。`SELECT user_id, event_type FROM events WHERE event_date = '2024-06-01'` 只扫描一天的分区和两列，大约 5 GB（约 \$0.03）。
