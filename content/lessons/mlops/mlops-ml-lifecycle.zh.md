## 为什么重要
面试官想知道你不仅能在 notebook 里训练模型，还能把模型上线并让它*持续有效*。生产环境中大多数 ML 故障来自数据和流程，而不是算法。

## 概念
ML 生命周期是一个循环，而不是一条直线：

1. **界定范围**：定义业务指标、模型驱动的决策，以及基线（规则或启发式方法）。
2. **数据**：收集、标注、校验、划分（关心未来表现时按时间划分），并做版本管理。
3. **开发**：特征、训练、评估、错误分析、实验跟踪。
4. **部署**：打包模型，选择服务模式（批处理、在线、流式），通过 shadow、canary 或 A/B test 逐步上线。
5. **监控**：服务健康（延迟、错误）、数据质量、漂移，以及业务和模型指标。
6. **重训练 / 下线**：按计划、按触发条件，或在监控发现性能衰减时进行。然后回到第 2 步。

**模型为什么会衰减**：
- **数据漂移**（协变量偏移）：$P(X)$ 变化，例如出现新的用户群体。
- **概念漂移**：$P(Y \mid X)$ 变化，例如欺诈者调整了手法。
- **上游故障**：schema 变更或某一列全是空值。
- **训练-服务偏差（training-serving skew）**：特征在离线和在线的计算方式不同。使用 feature store 或共享转换代码可以避免。

**检测漂移**：对每个特征比较参考窗口和线上窗口，可使用**群体稳定性指标（PSI）**，$\text{PSI} = \sum_i (a_i - e_i)\ln(a_i / e_i)$，对各个分箱求和，其中 $e_i$ 和 $a_i$ 分别是期望和实际的分箱占比。经验法则：$<0.1$ 稳定，$0.1$ 到 $0.25$ 中等，$>0.25$ 显著偏移。KS 检验和 Jensen-Shannon 散度是替代方案。

**标签到达滞后**（流失标签要 30 天），所以先监控输入漂移和代理指标，等标签到达后再监控真实指标。

**成熟度层级**：手动 notebook，然后是自动化训练流水线（持续训练），再到流水线本身的 CI/CD。

## 示例讲解
一个贷款违约模型训练时，申请人的收入分箱占比为 50/30/20%（低/中/高）。本月线上分布为 30/30/40%。

$$\text{PSI} = (0.30-0.50)\ln\tfrac{0.30}{0.50} + 0 + (0.40-0.20)\ln\tfrac{0.40}{0.20} = 0.1022 + 0.1386 \approx 0.24$$

这已接近显著偏移的边缘，所以应通知负责人，检查人群变化，并在新标注数据上评估性能，然后再决定是否重训练。

> [!TIP] 面试技巧
> - 把生命周期描述为一个循环，并说明你会在哪里做自动化：校验、重训练触发和回滚。
> - 区分数据漂移、概念漂移和训练-服务偏差，并各说出一种检测方法（PSI/KS、新标签上的性能、特征一致性测试）。
> - 陷阱：在漂移或被污染的数据上盲目重训练可能让情况更糟；应通过与 champion 模型对比验证来把关。
