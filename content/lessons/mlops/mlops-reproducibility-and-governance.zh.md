## 为什么重要
监管机构、审计人员和同事会问：是哪个模型做出了某个决策，你能否重新构建它。可复现性和治理把 ML 从笔记本变成可审计的系统，是高级岗位面试的常见话题。

## 概念
**可复现性** = 相同的**代码 + 数据 + 配置 + 环境 + 随机性**得到相同的模型（或在声明容差内相同的指标）。
- **代码**：每次运行都记录 git commit SHA；没有未提交的改动。
- **数据**：不可变、带版本的快照（DVC、lakeFS、Delta/Iceberg time travel）或内容哈希；记录查询语句和时间窗口。
- **配置**：超参数和特征定义保存在文件中并随运行一起记录，而不是在笔记本里手敲。
- **环境**：固定依赖（lock 文件）、容器镜像 digest、硬件/驱动版本。
- **随机性**：为 Python、NumPy 和框架设置种子；使用带种子的划分（或基于 id 哈希的划分）。在 GPU 上（非确定性 kernel、并行归约）以及数据顺序变化时，逐位相等仍可能失败，所以要定义“足够接近”。
- **跟踪**：实验跟踪器（MLflow、W&B）保存参数、指标、产物，并把运行 → 数据版本 → 代码 SHA 关联起来。流水线让各步骤可端到端重新运行。

**治理** = 谁可以在什么证据下做什么：
- 带阶段和**审批**的**模型 registry**（staging → production 需要审核）；不可变版本，以及谁在何时晋升了什么的**审计日志**。
- **血缘（lineage）**：对任何一次预测，都能追溯到模型版本、训练运行、数据集版本和特征。每次预测都记录模型版本。
- **文档**：**model card**（预期用途、训练数据、按切片的指标、局限性）和数据说明书。
- **风险与合规**：公平性和偏差检查、必要时的可解释性、隐私（PII 最小化、GDPR 删除/保留）、访问控制，以及模型风险管理（SR 11-7）和欧盟 AI 法案风险分级等监管框架。
- **运营制度**：责任人、值班、复审周期，以及淘汰陈旧模型。

## 示例讲解
审计人员问：“3 月 3 日是哪个模型拒绝了贷款申请 #8841，你能复现吗？”预测日志给出 `model_version = 14`。registry 把 v14 映射到运行 `a3f9`，该运行记录了 git SHA `7c1d2e`、数据集快照 `loans@2024-02-15`（内容哈希）、配置 `cfg.yaml`、种子 42 以及镜像 digest `sha256:ab12...`。重新运行该运行得到的 AUC 在 0.001 以内一致，model card 显示风险团队已批准。没有这条血缘，诚实的回答只能是“我们说不清”。

> [!TIP] 面试技巧
> - 把可复现性定义为代码 + 数据 + 配置 + 环境 + 随机性，并说明如何记录每一项。
> - 把预测日志关联到模型版本、运行、数据版本和代码 SHA，使任何决策都可以被审计。
> - 治理不止于工具：registry 审批、model card、公平性与隐私审查、责任人和淘汰机制。
