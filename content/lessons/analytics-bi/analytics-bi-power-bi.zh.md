## 为什么重要

Power BI 主导着企业 BI。分析师和 BI 岗位的面试会考察“先建模再写度量值”的流程：在 Power Query 中整理数据，构建星型模型，编写 DAX 度量值，并保持高性能。

## 概念

**流程**：连接并转换（**Power Query**，M 语言）→ 建模（关系、星型模型）→ 度量值（**DAX**）→ 视觉对象并发布到服务端（刷新、RLS、工作区）。

**Power Query**：可重复执行的 ETL 步骤列表。尽早删除列、设置类型、合并/追加、逆透视。**查询折叠（query folding）**会把步骤作为 SQL 下推回源数据库，所以把可折叠的步骤放在前面。

**数据建模**：一个事实表（粒度，例如订单行）被维度表（日期、产品、客户）包围，使用一对多、单向的关系。除非有充分理由，否则避免多对多和双向筛选。为时间智能标记一个规范的**日期表**。存储模式：**导入**（快，VertiPaq 压缩，定时刷新）、**DirectQuery**（实时，较慢）、**复合模式**。

**DAX 要点**
- **计算列**：按行计算，在刷新时生成并存储。**度量值**：在查询时于当前**筛选上下文**中计算；不占存储。
- **行上下文**（逐行迭代，例如 `SUMX`）与**筛选上下文**（切片器、视觉对象的行/列）。`CALCULATE` 修改筛选上下文，是核心函数。
- **时间智能**：`SAMEPERIODLASTYEAR`、`DATESYTD`、`TOTALYTD`（需要连续的日期表）。
- 用 `DIVIDE` 做安全除法，用 `VAR` 提高可读性和速度。

**安全与共享**：行级安全（用 DAX 筛选的角色）、工作区/应用、通过网关为本地数据源定时刷新。

## 示例讲解

基于与 `DimChannel` 及已标记的 `Date` 表关联的 `FactSales` 事实表编写的度量值：

```dax
Sales = SUM ( FactSales[Amount] )

Sales Online =
CALCULATE ( [Sales], DimChannel[Channel] = "Online" )

Sales LY =
CALCULATE ( [Sales], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

YoY % =
DIVIDE ( [Sales] - [Sales LY], [Sales LY] )
```

假设 2024 年销售额为 1.2M（其中线上 0.45M），2023 年为 1.0M。在选中 2024 年切片器的视觉对象中：`[Sales]` = 1.2M，`[Sales Online]` = 0.45M，`[Sales LY]` = 1.0M，`[YoY %]` = $(1.2 - 1.0)/1.0 = 20\%$。同样的度量值会对每个月份、地区或产品重新计算，因为每个单元格的筛选上下文不同；你不需要为每种切分单独写公式。

> [!TIP] 面试技巧
> - 各用一句话解释筛选上下文和行上下文；这是最常见的 DAX 问题。
> - 被问到最佳实践时，说“星型模型、单向关系、用度量值而不是计算列”。
> - 陷阱：对 20 亿行的表使用导入模式，或对所有数据都用 DirectQuery；要了解取舍，以及何时使用聚合或增量刷新。
