title: 留存与流失
---

## 为什么重要
留存是与长期增长关系最紧密的指标。面试官会让你精确定义流失，用 SQL 从活动表中算出来，并解释为什么流失率的小幅变化影响如此之大。

## 概念
**定义**（务必说明周期和分母）：
- **留存率** $= \dfrac{\text{起始人群中期末仍活跃的用户数}}{\text{起始人群}}$。
- **流失率** $= 1 - \text{留存率}$，针对同一人群。
- **类型**：**N 日留存**（注册后恰好第 N 天活跃）、**滚动或无界留存**（第 N 天及之后活跃）、**区间留存**（在某个窗口内活跃）。数字差别很大，要说明你用的是哪一种。
- **客户流失与收入流失**：**净收入留存**（NRR）包含扩张收入，所以在客户流失为正时也可以超过 100%。
- **订阅流失与参与度流失**：合同型（取消日期已知）与非合同型（连续 $X$ 天不活跃，阈值是任意的；应根据活跃间隔分布来选择）。

**为什么重要**：月流失率恒定为 $c$ 时，预期生命周期为 $1/c$。把流失率从 5% 降到 4%，生命周期从 20 个月升到 25 个月，LTV 提升 25%。留存曲线应当趋于平缓；一直跌向零的曲线说明没有核心用户群。

**用 SQL 计算流失**：取起始人群（$m$ 月活跃），左连接 $m+1$ 月的活动，统计没有匹配的用户。要注意：
- 对用户做*去重*计数；每个用户可能有多个事件。
- 之后回流（resurrected）的用户，在中间那个月仍然算流失。
- $m+1$ 月新获取的用户不属于起始人群。

**解读下降**：区分新用户留存（引导问题）与存量用户留存（产品或市场问题），并按渠道、平台和套餐细分。

## 示例讲解
月活跃用户：1 月 {1, 2, 3, 4, 5}；2 月 {1, 2, 4, 6}。

- 起始人群（1 月）= 5 名用户。
- 2 月留存 = {1, 2, 4} = 3。用户 6 是新用户，忽略。
- 留存率 $= 3/5 = 60\%$，流失率 $= 2/5 = 40\%$（用户 3 和 5）。

```sql
SELECT COUNT(*) AS jan_users,
       COUNT(f.user_id) AS retained,
       ROUND(1.0 * (COUNT(*) - COUNT(f.user_id)) / COUNT(*), 2) AS churn_rate
FROM monthly_active j
LEFT JOIN monthly_active f
  ON f.user_id = j.user_id AND f.month = '2024-02'
WHERE j.month = '2024-01';
```

`COUNT(f.user_id)` 只统计匹配上的行，所以两者之差就是流失用户数。如果写成 `WHERE f.month = ...`，左连接会变成内连接，悄悄丢掉流失用户。

> [!TIP] 面试技巧
> - 在计算之前先定义留存的周期、分母和类型（N 日留存还是滚动留存）。
> - 说明流失率变化一个百分点就会显著改变生命周期和 LTV（$1/c$），这就是留存比获客微调更重要的原因。
> - 留意 LEFT JOIN 陷阱：对右表的过滤放在 ON 而不是 WHERE；并把新用户排除在起始人群之外。
