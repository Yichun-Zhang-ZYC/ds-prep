---

## 为什么重要
“一个很小的按钮改动带来了 +20% 的提升”或“指标下降了，没人知道原因”是经典的面试题。出人意料的结果更可能是 bug 而不是突破（Twyman 定律：任何看起来有趣或与众不同的数字通常都是错的）。面试官想看到一套系统化的排查流程。

## 概念
从最可能、最容易检查的原因，逐步排查到最不可能的：

1. **数据与数据管道**：埋点改动、某个变体丢失事件、机器人流量、重复事件、指标定义变化、时区或日期边界 bug。
2. **分流**：整体和**各细分内部**的**样本比例失衡**（SRM）；用户在变体之间切换；两组的触发条件不一致。
3. **分析**：分析单位错误（会话 vs 用户）、离群值主导均值、偷看结果、多重比较、分母不匹配的比率指标。
4. **时间效应**：新奇效应或首因效应、节假日、同时进行的其他上线或营销活动、某个地区的服务中断。
5. **构成（辛普森悖论）**：当两组的细分构成不同时，整体结果可能指向一个方向，而每个细分都指向相反方向。
6. **真实效应**：只有排除了以上原因后，才去寻找真正的机制，并尝试复现。

对于实验之外的指标下降，按**时间**（突然还是逐渐）、**平台 / 应用版本**、**地区**、**流量来源**、**新用户 vs 老用户**细分，并把指标拆解成各个组成部分（例如转化 = 访问 × 访问到加购 × 加购到购买）。

## 示例讲解
一个结账实验显示：对照组转化率 8%，处理组 13%。按设备拆分：

| 细分 | 对照组 | 处理组 |
|---|---|---|
| 移动端 | 48 / 800 = 6% | 10 / 200 = 5% |
| 桌面端 | 32 / 200 = 16% | 120 / 800 = 15% |
| **整体** | 80 / 1000 = 8% | 130 / 1000 = 13% |

处理组在两个细分中都**更差**，但它分到的大多是转化率更高的桌面端用户。这就是辛普森悖论，而细分内部 80/20 对 20/80 的分配本身就是一个危险信号：很可能存在分流 bug（例如某个重定向丢掉了移动端用户）。在解读任何结果之前，先修好分流。

```reveal
  "prompt": "Case：实验显示处理组的人均收入提升了 15%，但中位数不变，转化率也持平。你会调查什么？",
  "answer": "均值变了、而中位数和转化率持平，说明是少数极端值在起作用。\n\n1. **离群值**：查看每组收入最高的用户。处理组里一个大客户或批量 / B2B 买家就能拉动均值。用缩尾（winsorize）或封顶后的收入、或截尾均值重新分析。\n2. **机器人 / 欺诈 / 测试账号**：异常的订单金额或模式；检查它们是否被一致地排除。\n3. **埋点**：某个变体中购买事件重复记录，或货币换算 bug。\n4. **分流**：做 SRM 检查；确认高价值用户没有被（例如某条定向规则）导入处理组。\n5. **真实效应？** 如果封顶后提升仍然存在，并且分布在许多用户身上（例如购买者的客单价提高），那它可能是真的；检验每位购买者的收入，并复现实验。\n\n给出的结论：在结果经得起对离群值稳健的分析之前，不要汇报 +15%。"
}
```

> [!TIP] 面试技巧
> - 引用 Twyman 定律：出人意料的结果通常是 bug；庆祝之前先检查数据和分流。
> - 给出有顺序的检查清单（数据管道 → 分流 → 分析 → 时间 → 构成 → 真实效应），而不是随意猜测。
> - 对于指标下降，先问“突然还是逐渐？”，再做细分，并把指标拆解成漏斗的各个环节。
