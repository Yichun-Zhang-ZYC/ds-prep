## 为什么重要
几乎每一道实验类 case 面试最后都会问：“那么，你会上线吗？”只回答一个词是不及格的。面试官想看到一个结构化的决策：综合考虑数据是否可信、统计显著性与实际显著性、护栏指标以及业务背景。

## 概念
按顺序回答四个问题：

1. **结果可信吗？** 检查样本比例失衡（SRM）、埋点日志、实验时长（至少覆盖一个完整的周周期）以及新奇效应。如果数据有问题，就到此为止。
2. **主要指标的效果是真的吗？够大吗？** 看置信区间，而不仅仅是 p 值。把它和**最小实际效果**（值得承担上线与维护成本的最小提升）比较。
3. **有没有护栏指标变差？** 延迟、崩溃、退订、收入。即使主要指标赢了，护栏指标的显著恶化通常也会阻止上线。
4. **业务背景怎么说？** 改动的成本、可回滚性、战略价值，以及不同细分人群的效果是否不同。

把提升的置信区间和实际阈值 $\delta$ 对照：

| 提升的置信区间 | 决策 |
|---|---|
| 完全高于 $\delta$ | 上线（若护栏指标正常） |
| 高于 0 但包含低于 $\delta$ 的值 | 显著但未必值得：权衡成本，或延长实验 |
| 包含 0，且很宽 | 功效不足：延长或重新设计；不要说成“没有效果” |
| 包含 0，且紧贴 0 附近 | 确实“没有有意义的效果”：除非有其他理由，否则不上线 |
| 完全低于 0 | 不上线；弄清原因 |

## 示例讲解
新的结账流程：转化率提升 +1.2%，95% 置信区间 [+0.4%, +2.0%]，$\delta$ = 0.5%。SRM 检查通过，实验运行了 14 天。护栏指标：页面延迟 +30 ms（不显著），退款率不变。

置信区间高于 0，但下限（0.4%）略低于 $\delta$。区间的大部分超过了门槛，护栏指标干净，改动也容易回滚。建议：**上线**，保留一个小的 holdout 组来确认长期效果，并监控延迟。

> [!TIP] 面试技巧
> - 先说框架（“可信度 → 主要指标 → 护栏指标 → 业务背景”），再套用它。
> - 始终区分统计显著性和实际显著性；报出置信区间。
> - 最后给出明确的建议以及后续动作（holdout、监控、细分分析）。只说“看情况”而不做决定会被扣分。
