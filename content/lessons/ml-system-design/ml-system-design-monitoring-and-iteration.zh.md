## 为什么重要
模型会悄悄退化：服务仍返回 200 OK，但因为世界变了，准确率在下降。“上线后你如何监控这个模型，什么时候重新训练？”几乎是每场 ML 设计面试的收尾问题。

## 概念
监控四个层面：
1. **系统健康**：延迟（p50/p95/p99）、错误率、吞吐量、内存/GPU、超时、降级（fallback）比例。
2. **数据质量**：schema 变化、空值率、越界值、特征缺失或过期、训练/服务偏差（skew）。
3. **数据与预测漂移**（不需要标签）：输入特征分布的变化（**协变量漂移**）以及预测分数分布的变化。工具：按分箱计算的 **PSI** $=\sum_i (a_i - e_i)\ln(a_i/e_i)$（经验法则：<0.1 稳定，0.1-0.25 中等，>0.25 严重）、KS 检验、JS 散度。
4. **模型表现**（需要标签）：AUC、精确率/召回率、校准、业务 KPI，并按人群切片。标签常常延迟到达（拒付要几周），所以使用**代理指标**（点击率、分数分布）和延迟标签看板。

**概念漂移**指 $P(y \mid x)$ 发生变化（欺诈手法在演变），仅靠输入监控无法发现。注意**反馈回路**：模型自己的决策会影响未来的训练数据（只能看到被批准的贷款或被展示的内容的结果），所以要保留探索或留出（holdout）切片。

**迭代**：
- **重训触发条件**：定时（每日/每周）、漂移或指标阈值、新数据量。优先使用带验证关卡的自动化流水线。
- **安全发布**：影子模式、灰度或 A/B、**冠军/挑战者**、即时回滚、对模型、数据和代码做版本管理。
- **告警**：对可执行的分级阈值告警，避免告警疲劳；准备运行手册和降级方案（上一版模型或规则）。

## 示例讲解
某流失模型的 `tenure` 特征在训练时的分箱占比为 $e = (0.5, 0.3, 0.2)$；本周流量为 $a = (0.3, 0.3, 0.4)$。
PSI $= (0.3-0.5)\ln(0.6) + 0 + (0.4-0.2)\ln 2 = 0.1022 + 0.1386 \approx 0.24$，属于中等漂移，接近 0.25 的警戒线。下一步：重训之前先排查流水线 bug（新用户群或坏掉的 join）；如果漂移是真实的，且有标签的数据上 AUC 已下降，再重训。

> [!TIP] 面试技巧
> - 区分系统健康、数据质量、漂移和真实表现，并说明哪些需要标签。
> - 说出用 PSI/KS 监控漂移、用代理指标应对标签延迟，以及概念漂移与协变量漂移的区别。
> - 闭环：重训触发条件、验证关卡、影子/灰度发布、回滚，以及用于对抗反馈回路的 holdout。
