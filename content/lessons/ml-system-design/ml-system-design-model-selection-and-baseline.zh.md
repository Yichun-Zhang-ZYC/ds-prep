## 为什么重要
面试官想看到的是有理有据的建模路径，而不是你偏爱的某个算法：从简单开始，为每一步增加复杂度提供理由，并清楚基线是什么。“先打败一个强基线”是资深机器学习工程师的标志。

## 概念
**基线阶梯**（只有当收益值得复杂度的代价时才往上走）：
1. **无 ML / 启发式**：多数类、全局均值、“最热门”、上一个值、规则。给出下限和业务门槛。
2. **线性/逻辑回归**配合好的特征：快、可解释、擅长稀疏数据、容易调试。
3. **梯度提升树**（XGBoost、LightGBM）：在表格数据上通常最好，几乎不用怎么调参。
4. **深度模型**：用于非结构化输入（文本、图像、音频）、巨大的 ID 空间（嵌入、双塔）、序列或多任务学习。标注稀缺时使用预训练/基础模型并微调。

**根据约束选择**：数据规模和类型、每次预测的延迟与成本、可解释性或监管要求、训练和重训频率、团队技能、冷启动表现，以及维护难度。

大型目录使用**多阶段系统**：廉价的**召回/候选生成**（双塔 + ANN、热门、共现）把百万级缩小到数百个，然后由更重的**排序器**打分，再由**重排**应用业务规则和多样性。每个阶段都在召回率与成本之间权衡。

**基线规范**：在*相同*的划分和指标上比较；报告相对基线的提升，而不是绝对数值；要与当前线上系统比较，而不只是玩具基线。对于不平衡数据，多数类基线的准确率没有意义：应使用相对基准率的提升度或 PR-AUC。

可以提到集成、蒸馏（用大教师模型训练小学生模型），以及 LLM 类任务的自建 vs 购买/API 选项，但第一个版本要足够简单，能够上线。

## 示例讲解
流失预测：10,000 名用户，流失率 5%，即 500 名流失用户。
- 多数类基线：永远预测“留存”，准确率 95%，召回率 0。作为门槛毫无用处。
- 对前十分位（1,000 名用户）随机投放，能找到 $0.05 \times 1{,}000 = 50$ 名流失用户。
- 梯度提升模型的前十分位包含 300 名流失用户：精确率 0.30，召回率 $300/500 = 0.6$，**提升度 = 300/50 = 6**。
- 逻辑回归的前十分位包含 240 名流失用户（提升度 4.8）。GBDT 每个十分位多找出 60 名流失用户；若每人价值 \$50，则每次活动多赚 \$3,000。如果这超过了它额外的服务和维护成本就上线它；否则上线逻辑回归模型。

> [!TIP] 面试技巧
> - 先说明基线（启发式，然后逻辑回归，然后 GBDT），并说清楚什么样的结果才值得做得更复杂。
> - 把模型选择与约束挂钩：数据类型和规模、延迟、可解释性、冷启动、维护成本。
> - 对于大型目录，描述召回、排序、重排三个阶段以及每个阶段优化什么。
