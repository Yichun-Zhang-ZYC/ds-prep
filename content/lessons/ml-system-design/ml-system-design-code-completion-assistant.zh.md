## 为什么重要
“设计 Copilot 式的代码补全”结合了严格延迟预算下的 LLM 服务、用于上下文的检索，以及不寻常的产品指标（接受率、被接受代码的留存）。面试官借此看你是否会权衡延迟与质量、构建上下文流水线，以及做超出离线基准的度量。

## 概念
**问题定义**：开发者输入时，显示可按 Tab 接受的行内“幽灵文本”（一行、一个代码块或一次编辑）。聊天和 agent 模式是另外的产品；参见 *LLM 驱动的 agent 系统*。核心问题是在几百毫秒内，根据不完整的文件生成*有用的*补全，并知道何时保持安静。

**延迟预算**：打字的节奏意味着，用户再次输入后才到达的建议就浪费了。单行补全的 p50 目标约 200-300 ms，p95 低于约 1 秒。预算拆分：网络、上下文组装、prefill、解码、后处理。策略：
- **防抖与取消**：等待约 50-100 ms 的空闲，下一次按键时取消进行中的请求。
- **小而快的模型**（蒸馏/量化，数十亿参数），输出短，在行尾或块尾设置停止 token。
- **前缀 KV 缓存复用**：连续请求几乎共享整个前缀。**推测解码**（草稿模型或基于文件的 n-gram 查找）能加速解码，因为补全经常复制附近的代码。
- **连续批处理**和区域化 GPU 池；优化延迟而非吞吐。

**模型**：用**中间填充（FIM）**训练的代码 LLM：把文档拆成前缀、中间和后缀，让模型学会在给定两侧的情况下生成中间部分，这与光标位于文件中间相匹配。使用许可宽松的代码做训练，并去重和做质量过滤；数据中不得包含密钥和 PII。

**上下文流水线**（往往比模型大小更能提升质量）：光标前的前缀和光标后的后缀，然后是导入语句和外围函数签名、最近编辑和已打开文件的片段（便宜且高度相关），以及仓库检索（对符号级块做 BM25 或嵌入检索，可选 LSP/类型信息）。把它们装进固定的 token 预算，最相关的内容放在离光标最近处。

**门控与后处理**：一个小分类器决定是否显示，特征包括光标位置、语言、近期接受情况和打字速度，使低价值的建议根本不出现。生成之后：在语法边界处截断，移除与后缀重复的文本，平衡括号（用 tree-sitter 解析），并按策略要求过滤密钥、易受攻击的模式和与公开代码逐字匹配的内容。

**评估**：
- *离线*：在函数级基准上基于执行的 **pass@k**（无偏估计 $1-\binom{n-c}{k}/\binom{n}{k}$，来自 $n$ 个样本中有 $c$ 个通过），以及仓库级评估：在留出的真实仓库中遮蔽代码片段，评分精确匹配、编辑相似度或测试是否仍通过。污染很重要，所以使用新的仓库。
- *线上*：接受率（接受数 / 展示数）、**留存字符数**（几分钟后仍在文件中）、AI 编写的字符数或代码占比、展示延迟，以及在受控实验中开发者层面的结果（任务完成时间）。仅看接受率会奖励简短、显而易见的补全，且可被操纵，所以要配合留存和延迟护栏。

**反馈与隐私**：接受/拒绝/接受后编辑事件会成为重排和偏好数据。企业客户期望需主动同意（opt-in）、默认不用其私有代码训练，并可选本地部署或 VPC 部署。

## 示例讲解
延迟（仅作说明）。网络 40 ms，上下文组装 30 ms，使用缓存前缀的 prefill 80 ms，24 个 token 的补全按每 token 10 ms 解码 = 240 ms。总计 $40+30+80+240=390$ ms，超出 300 ms 的目标。推测解码带来约 2 倍解码加速，解码降到 120 ms：总计 270 ms。达标。

门控（仅作说明）。在 1,000 次触发事件中：
- 总是展示：展示 1,000 次，接受率 12%，接受 120 次。
- 使用门控，只展示 40% 的事件，这些事件的接受率达到 30%：$400\times0.30=120$ 次接受，同时少了 600 次干扰性建议。

接受数相同，噪声却少得多。如果 85% 的被接受补全被保留，平均 40 个字符，则留存字符数 $=120\times0.85\times40=4{,}080$，在门控方案下约合每次展示 10.2 个字符。

pass@k：$n=10$ 个样本中 $c=2$ 个正确，$\text{pass@3}=1-\binom{8}{3}/\binom{10}{3}=1-56/120=0.533$。朴素的 $3\times0.2=0.6$ 会重复计数（同时包含两个正确样本的抽取被算了两次），$k$ 更大时甚至可能超过 1，所以要使用组合形式的估计量。

> [!TIP] 面试技巧
> - 以延迟预算为锚点，并列出具体手段：防抖、取消、KV 缓存、推测解码。
> - 提到 FIM 和上下文流水线；上下文质量往往比模型大小更重要。
> - 不要止步于接受率：加上留存字符数和延迟护栏。
> - 覆盖门控（何时不显示）、许可/安全过滤和隐私。
