## 为什么重要
“设计推荐信息流”（首页 feed、视频、电商）是最常见的 ML 系统设计题。它考察你能否在延迟限制下，把召回、排序、目标、冷启动和评估结合起来。

## 概念
遵循框架：需求 $\to$ 数据 $\to$ 模型 $\to$ 服务 $\to$ 评估。

1. **需求与目标**：规模（用户、物品、QPS）、延迟（端到端约 200 ms）、新鲜度。目标是用户的长期价值，而不仅仅是点击；标题党优化的是错误的东西。加入护栏指标（多样性、创作者公平、安全、投诉）。
2. **漏斗**（每次请求无法对数百万物品打分）：**候选生成**（数百万 $\to$ 约 1,000）$\to$ **排序**（约 1,000 $\to$ 约 100）$\to$ **重排 / 策略**（约 100 $\to$ 展示约 20）。
   - **召回**：合并多路来源：带 ANN 索引（FAISS/ScaNN/HNSW）的**双塔**embedding、协同过滤、物品到物品的共同互动、关注/订阅的作者、热门/新内容、规则。
   - **排序**：更重的模型（GBDT 或深度多任务网络），使用用户、物品、上下文和交叉特征。**多任务**输出头（p(点击)、p(点赞)、p(分享)、E[观看时长]、p(不感兴趣)）合成为 $\text{score} = \sum_k w_k\,\hat p_k$，权重通过线上实验调整。
   - **重排**：多样性（MMR）、去重、新鲜度、业务规则、广告混排、探索位。
3. **数据与标签**：记录曝光及其位置，以及服务时刻的特征（避免泄漏和偏差）；正例来自点击/观看/点赞，负例来自曝光未点击；**位置偏差**（训练时把位置作为特征、服务时去掉，或使用逆倾向加权）；为规模做采样；按时间划分数据。
4. **冷启动**：新用户（引导、热门、上下文）和新物品（内容 embedding、创作者信号、用 bandit 探索）。
5. **服务**：批量预计算的用户/物品 embedding 和候选、来自 feature store 的在线特征、ANN 查询、缓存、超时时回退到热门内容。
6. **评估**：离线 recall@K、NDCG、在时间划分上的 AUC/log-loss 以及校准检查；然后做 **A/B 测试**，看参与度（会话、观看时长、留存）及护栏指标。注意**反馈回路**和信息茧房：记录探索流量、保留 holdout、频繁重训。

## 示例讲解
有 1000 万视频、延迟预算 200 ms 的视频应用的漏斗：召回返回 1,000 个候选（30 ms），特征获取（30 ms），排序器对 1,000 个候选打分（60 ms），重排裁剪到 20 个（10 ms），还剩约 70 ms 用于网络和余量。
相关性排序 $[3, 2, 0, 1]$ 的 NDCG@4：DCG $= \frac{7}{\log_2 2} + \frac{3}{\log_2 3} + 0 + \frac{1}{\log_2 5} = 7 + 1.893 + 0.431 = 9.323$。理想顺序 $[3,2,1,0]$：$7 + 1.893 + 0.5 = 9.393$。NDCG $= 9.323/9.393 \approx 0.993$。

> [!TIP] 面试技巧
> - 始终说明漏斗（召回、排序、重排）及原因，并给出每个阶段的物品数量。
> - 选择超越点击的目标（多任务、长期价值）并说出护栏指标。
> - 涵盖位置偏差、冷启动、反馈回路，以及从离线 NDCG 到线上 A/B 的评估。
