## 为什么重要
特征决定了模型的大部分上限，也带来了大部分生产环境的 bug。面试官希望看到结构化的特征清单、对高基数数据合理的编码方式，以及对泄漏和训练/服务偏差的意识。

## 概念
**特征清单**（要说出这几类）：用户（历史、人口属性、生命周期统计）、物品（内容、价格、热度）、上下文（时间、设备、位置），以及**交互/交叉特征**（用户 × 类别偏好、该用户对这类物品的点击率）。

**编码**
- 数值：对重尾分布取对数/截断；线性模型和神经网络需标准化（树模型不需要）；分桶以捕捉非线性。
- 周期性时间（小时、星期）：$(\sin\frac{2\pi h}{24}, \cos\frac{2\pi h}{24})$，使 23 点和 0 点彼此接近。
- 低基数类别：独热编码。高基数 ID：**嵌入**、哈希技巧，或带平滑的**目标编码**，并用折外方式计算以避免泄漏：$\text{enc}(c) = \frac{n_c \bar y_c + m \bar y}{n_c + m}$（$m$ 为平滑强度）。
- 文本/图像：预训练嵌入。缺失值：填充并加一个“是否缺失”标记。
- 窗口聚合（最近 1 小时/7 天/30 天的点击）可以捕捉时效性和趋势。

**正确性才是真正的风险**
- **时间点正确性**：时刻 $t$ 的训练样本只能使用时间戳 $\le t$ 的数据（as-of 连接）。否则模型会偷看未来。
- **训练/服务偏差**：离线和在线使用相同的特征代码和定义（特征仓库或共享的转换库）；记录服务时的特征用于训练。
- **新鲜度分层**：批处理（每天）、近实时（流式计数器）、请求时（上下文）。每一层都增加成本和延迟；只在能改善指标的地方投入。
- 警惕代理标签的特征（例如欺诈模型中的“已退款”）以及受保护属性。

## 示例讲解
为欺诈模型对 `merchant` 做目标编码。全局欺诈率 $\bar y = 0.10$。商户 A 有 $n = 5$ 笔交易，其中 3 笔欺诈（$\bar y_A = 0.6$）；平滑系数 $m = 20$。
$$\text{enc}(A) = \frac{5 \cdot 0.6 + 20 \cdot 0.10}{5 + 20} = \frac{3 + 2}{25} = 0.20.$$
由于 5 个样本不可靠，原始的 0.6 被向先验收缩。拥有 2,000 笔交易的商户则几乎保留自己的比率。

时间点：用户的 `avg_basket_30d` 每天重新计算。对于 2024-05-10 14:00 的订单，必须读取截至 2024-05-10 00:00（或更早）的值，绝不能读取包含该订单本身的 2024-05-11 的值。

> [!TIP] 面试技巧
> - 按用户 / 物品 / 上下文 / 交叉特征组织特征，然后讨论新鲜度（批处理 vs 流式 vs 请求时）。
> - 主动提到时间点正确性和训练/服务偏差；这是高级别候选人的信号。
> - 对高基数 ID，提出嵌入或平滑的（折外）目标编码，并解释泄漏风险。
