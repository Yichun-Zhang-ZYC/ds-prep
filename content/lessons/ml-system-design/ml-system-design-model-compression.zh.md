## 为什么重要
离线表现最好的模型往往无法上线：对延迟 SLO 来说太慢，对手机来说太大，或每次请求成本太高。压缩是缩小这一差距的标准工具箱，面试官期望你了解每种技术的权衡。

## 概念
主要技术：
- **量化**：用更少的比特存储权重（有时也包括激活值）。fp32 $\to$ fp16/bf16 $\to$ int8 $\to$ int4。对称 int8：$s = \max|x|/127$，$q = \text{round}(x/s)$，$\hat x = s q$；每个值的误差 $\le s/2$。**训练后量化（PTQ）**只需校准数据；**量化感知训练（QAT）**在训练中模拟舍入，能恢复更多精度。LLM 的变体：GPTQ、AWQ、int4 仅权重量化。要获得真实加速需要硬件/内核支持；按通道或按组设置缩放因子可减小误差。
- **剪枝**：移除权重（非结构化，稀疏度高但在 GPU 上加速有限）或整个通道/注意力头/层（结构化，有真实加速）。通常之后需要微调。N:M 稀疏（2:4）有硬件支持。
- **知识蒸馏**：训练一个小的**学生**模型去匹配大的**教师**模型的软输出：$\mathcal L = \alpha\,\text{CE}(y, p_s) + (1-\alpha)\,T^2\,\text{KL}(p_t^{T} \| p_s^{T})$，其中 $T$ 为温度。通常能以很小的规模保留大部分质量（DistilBERT：小 40%，保留约 97% 的 BERT 性能，快 60%）。
- **低秩分解**（$W \approx AB$）、**权重共享**、**高效架构**（MobileNet）、**提前退出/级联**，以及对 LLM 的 **KV cache** 量化和推测解码。

**权衡与流程**：测量在关键指标上（并按切片）的质量下降，以及在**目标硬件**上的延迟/显存收益，然后迭代。通常先蒸馏，再剪枝/量化，并做验证。可结合缓存和批处理。模型大小 $= \text{参数量} \times \text{比特数}/8$ 字节。

## 示例讲解
70 亿参数的 LLM：fp16 $= 7\text{B} \times 2 = 14$ GB；int8 $= 7$ GB；int4 $= 3.5$ GB（外加少量缩放因子），消费级 GPU 就放得下。由于解码受显存带宽限制，权重更小也意味着 token 生成更快。
量化 $x = [0.5, -1.0, 0.25, 1.27]$：$s = 1.27/127 = 0.01$，所以 $q = [50, -100, 25, 127]$，这里反量化是精确的。像 $0.504$ 这样的值映射到 $q = 50$（误差 0.004，小于 $s/2 = 0.005$）。
