## 为什么重要
嵌入是 RAG、语义搜索和去重的检索骨干。面试官会问你如何选择模型、使用什么维度和相似度、领域和语言为什么重要，以及如何衡量一个嵌入模型是否适合你的数据。

## 概念
**嵌入模型**把文本（或图像、代码）映射为稠密向量，使语义相近的内容在空间中靠近。现代文本嵌入器是 Transformer 编码器（或基于 LLM），通过**对比学习**训练：把查询和相关段落的配对拉近，把批内负例推远。

**相似度**：余弦（角度）或点积；对于 **L2 归一化**的向量，余弦 = 点积，且排序与欧氏距离相同。要确认模型是针对哪一种训练的。

**选择模型**：
- **基准**：MTEB（及其多语言版本）在检索、分类和聚类上对模型排名；用它来缩小候选范围，然后**在你自己的查询上评估**，因为排行榜并不反映你的领域。
- **维度**：典型为 384 到 3072。更多维度可能意味着更好的质量，但会消耗内存、索引构建时间和延迟。**Matryoshka** 模型允许你截断到前 $d$ 个维度（然后重新归一化），质量平缓下降。
- **最大输入长度**：512 到 8k+ 个 token；更长的输入会被截断，所以块大小必须适配。
- **多语言与领域**：单语英文模型在其他语言上会失败；法律、生物医学和代码语料受益于专用或微调的模型。
- **托管 API 与开源**：API（OpenAI、Cohere、Voyage、Google）易用，但增加按 token 的成本、网络延迟和数据共享方面的顾虑；开源模型（BGE、E5、GTE、Nomic 等，通过 sentence-transformers 或 text-embeddings-inference）提供控制权，并能在 GPU 上以低成本批量嵌入。
- **非对称搜索**：查询短，文档长。许多模型需要**查询/文档前缀或指令**（例如 `query: ` 和 `passage: `）；漏掉它会悄悄降低结果质量。

**运维规则**：文档和查询必须由同一个模型（及版本）嵌入；更换模型意味着要**重新嵌入整个语料**。把模型 id 与每个向量一起存储。量化（float16、int8、二值）可以把内存减少 2 到 32 倍，召回损失很小。稠密嵌入可能漏掉精确词项（ID、罕见人名），这就是 BM25 混合搜索存在的原因。

**评估**：构建（查询，相关文档）配对，然后衡量检索的 recall@$k$、MRR 和 nDCG，而不是凭感觉检查。

## 示例讲解
一个有 1000 万个块的语料。使用 1,536 维 float32 向量：$10^7 \times 1536 \times 4$ 字节 $= 61.44$ GB；3,072 维则为 122.88 GB；使用 Matryoshka 截断后的 256 维 int8 索引：$10^7 \times 256 \times 1 = 2.56$ GB，缩小了 24 倍（会损失一点召回；要在评测集上检查，并可选择用完整向量对前几名候选重新打分）。

检索检查：有 2 个相关文档 {1, 2}；检索器返回 [5, 1, 9, 2]。Recall@2 = 1/2 = 0.5（前 2 名中只有文档 1）；recall@4 = 2/2 = 1.0。如果传给 LLM 的 top-3 上下文窗口只有 recall@3 = 0.5，那么改进嵌入器或加入重排序器，比调整提示词更能提升答案质量。

> [!TIP] 面试技巧
> - 用 MTEB 缩小候选，用你自己的标注查询和 recall@k 做决定；绝不要只凭排行榜选择。
> - 提到查询/文档前缀、归一化、维度与内存（Matryoshka、量化），以及更换模型会强制重新嵌入。
> - 承认稠密检索会漏掉精确匹配；把它与 BM25 和重排序器搭配使用。
