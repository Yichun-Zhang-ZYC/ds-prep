## 为什么重要
LLM 是无状态的：每次调用都从零开始。助手“记得”的一切，都是你的代码重新放回提示词中的内容。面试官会问：如何让长对话保持在上下文窗口之内、智能体如何跨会话记住用户，以及可能出什么问题。

## 概念
**短期记忆**是迄今为止的对话，保存在上下文窗口中。**长期记忆**存放在模型之外（向量库、键值存储、SQL），按需检索。长期记忆的常见划分：
- **语义记忆**：事实和偏好（“偏好公制单位”“在 Acme 工作”）。
- **情景记忆**：过去交互或任务运行的记录，可用作 few-shot 示例。
- **程序性记忆**：学到的指令或规则，常以更新后的系统提示词形式保存。

**管理短期历史**：
- **完整缓冲**：全部发送。简单，但成本和延迟随轮次增长，最终会溢出。
- **滑动窗口**：保留系统提示词加最近 $k$ 轮（或最近 $N$ 个 token）。便宜，但会忘记早期事实。
- **滚动摘要**：历史超过阈值时，让 LLM 把旧对话压缩成简短摘要，近期对话原样保留。有损；摘要可能丢失或扭曲细节。
- **检索式记忆**：为每条记忆做嵌入，按相关性取 top-$k$（可结合新近度和重要性，如 Generative Agents 论文）。

**写入路径**：每轮后提取候选记忆（LLM 或规则），去重或更新而不是一味追加（处理地址变更这类矛盾），附加元数据（时间戳、来源、用户 id），并设置 TTL。**读取路径**：用当前消息查询，按用户过滤，以清晰的标题注入提示词。

**常见陷阱**：过期或相互冲突的记忆、无关的召回干扰模型、未经同意或没有删除途径地存储 PII，以及**记忆投毒**（被写入长期记忆的提示词注入会跨会话持续存在）。模型必须精确无误的事实应放在数据库里，而不是摘要里。

## 示例讲解
上下文窗口 8,000 token；系统提示词 500；为回复预留 1,000；每轮平均 300 token。历史预算 $= 8000 - 500 - 1000 = 6500$，所以滑动窗口可容纳 $\lfloor 6500/300 \rfloor = 21$ 轮。

到第 20 轮时历史为 $20 \times 300 = 6000$ token。把它压缩成 300 token 的摘要并保留最近 4 轮（1,200 token）：提示词中的历史变为 $300 + 1200 = 1500$ token，减少了 $(6000 - 1500)/6000 = 75\%$。代价是多一次摘要调用以及部分细节丢失。

> [!TIP] 面试技巧
> - 尽早说出“模型无状态，应用有状态”；记忆本质上是上下文组装问题。
> - 按成本、对旧事实的召回能力和失效方式来比较窗口、摘要与检索。
> - 提到写入路径的卫生（去重、TTL、删除/同意）和记忆投毒；这能区分演示与生产。
