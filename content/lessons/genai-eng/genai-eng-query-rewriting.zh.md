## 为什么重要
用户写的查询往往含糊、口语化、包含多个部分（“那 Pro 套餐呢？”），而检索只能看到这个字符串。在检索前改写查询是提高召回的廉价手段，也是面试官问“你的 RAG 漏掉了相关文档，怎么办？”时的标准追问。

## 概念
常见技术，各自解决不同的失败模式：
- **对话压缩**：把追问加上聊天历史改写成独立问题（“那 Pro 套餐呢？”变成“Pro 套餐的价格是多少？”）。对聊天机器人必不可少；否则代词和省略会导致什么都检索不到。
- **多查询/查询扩展**：让 LLM 生成 3-5 个改写或子方面，分别检索再合并（去重、RRF 或轮询）。对含糊或词汇不匹配的查询可提高召回。
- **HyDE（假设文档 embedding）**：让 LLM 写一个假设的答案，用它的 embedding 代替问题的 embedding。答案比问题更像文档，所以 embedding 更靠近相关 chunk。风险：幻觉出的细节会误导检索；当模型缺乏领域知识时效果较弱。
- **后退一步提示（step-back）**：抽象成更宽泛的问题（“为什么 2021 年的故障持续了那么久？”改成“我们系统中长时间故障的常见原因是什么？”）以检索背景原理。
- **分解**：把多跳问题拆成子问题，依次或并行回答（“A 公司的 CEO 和 B 公司的创始人谁年纪更大？”）。
- **路由/元数据提取**：把查询变成结构化过滤（`year=2023`、`product=pro`）加语义部分（self-query 检索器）。

**成本与控制**：每次改写都增加一次 LLM 调用（延迟 300 ms-1 s），并引入一种失败模式（偏离用户意图）。使用小而快的模型、低 temperature，把原始查询保留在检索集合中，限制改写数量，缓存结果，并以相对无改写基线的 recall@k 来评估。

## 示例讲解
历史：用户问过 Basic 套餐的价格（\$10/月）；然后问“那 Pro 的呢？包含 SSO 吗？”。

1. 压缩：“Pro 套餐的价格是多少，是否包含 SSO？”
2. 分解：(a) “Pro 套餐价格”，(b) “Pro 套餐 SSO 支持”。
3. 每个子问题取前 3 条：得到 `[p1, p2, p3]` 和 `[s1, p2, s3]`。
4. 带去重的轮询合并：`p1, s1, p2, p3, s3`（重复的 p2 只保留在它第一次出现的位置）。现在 prompt 覆盖了两个方面，而把合并后的问题作为单个 embedding 往往会处理得不好。

> [!TIP] 面试技巧
> - 说出每种技术针对的失败模式：压缩（聊天上下文）、多查询（词汇不匹配）、HyDE（问题与文档之间的差距）、分解（多跳）。
> - 如实说明取舍：额外的延迟、成本和意图偏移。始终保留原始查询，并用 recall@k 和端到端答案质量来衡量。
> - 如果被问到对话机器人先试什么，回答结合聊天历史的对话压缩。
