## 为什么重要
从发票、合同、简历或临床记录中抽取字段，是价值最高也是最常被问到的 LLM 应用之一。面试考的是如何把一个不确定的模型变成可靠的流水线：模式、校验、重试、人工复核和按字段评估。

## 概念
机制方面请参见结构化输出和工具调用相关课程；这里讲的是系统视角。

1. **与业务一起定义模式**：每个字段都有类型、格式、允许取值，以及“缺失则为 null”。区分*缺失*和*未知*；禁止猜测。加入简短的字段说明和 2-3 个少样本示例，其中包括一个有难度的。
2. **流水线**：摄取（OCR/解析，见 PDF 案例）→ 可选地先分类文档类型并选用对应的模式 → 用模式约束的输出抽取（JSON schema / 工具调用 / 约束解码）→ **校验**（类型、枚举、正则、跨字段检查如 `subtotal + tax = total`、日期范围）→ **修复**（把校验错误信息带回去重新询问，重试 1-2 次）→ **规范化**（日期转 ISO、币种、与主数据做实体匹配）→ 把低置信度记录送人工复核 → 入库。
3. **置信度**：LLM 的校准较差，因此要组合多种信号：校验是否通过、2-3 次采样或两个提示词之间是否一致、值是否在原文中逐字出现（片段对齐）、以及可用时的 token 对数概率。要求抽取值附带原文引用，方便复核人员快速核对。
4. **长文档或多页文档**：按章节分块，逐块抽取，再按冲突规则合并（优先采用标注为“应付总额”的值，而非表格小计）；或使用带页码引用的长上下文模型。
5. **成本与吞吐**：用满足各字段目标的最便宜模型（常常是一个小模型加好的模式），离线任务用批处理 API，共享指令用提示词缓存，只在重试时使用更强的模型。
6. **评估**：由两人标注的标准集（100-500 份文档）；按字段计算精确率、召回率、F1（错误的值同时算作假阳性和假阴性；对存在的字段输出 null 算假阴性），再加上文档级“全部正确”比例和直通处理率。监控漂移：新的供应商/版式。

**常见坑**：只看总体准确率（掩盖了关键字段的薄弱）、为缺失字段编造看似合理的值、在测试集上调提示词、比较前不做格式规范化、不对模式和提示词做版本管理、OCR 质量差时悄悄失败。

## 示例讲解
示意：每月 50,000 张发票，6 个字段。300 张发票的标准集上，`total` 字段：280 个正确、8 个值错误、6 个在存在的字段上输出 null、6 个标准答案为 null 且模型正确输出了 null。

- $TP = 280$；$FP = 8$（错误值）；$FN = 8 + 6 = 14$（错误值加上弃权）。
- 精确率 $= 280/288 = 0.972$；召回率 $= 280/294 = 0.952$；$F_1 = 2PR/(P+R) \approx 0.962$。
- 路由：校验失败或两次采样抽取不一致的记录（假设占 18%）进入人工复核。这 14 条错误记录占 300 的 4.7%；如果复核能拦住其中 85%，残余错误率约降到 0.7%，而人工工作量只有 18%（而非 100%）。
- 成本估算：每张发票 2,000 输入 + 300 输出 token，小模型价格每百万 \$0.15 / \$0.60，即 $0.0003 + 0.00018 = 0.00048$ 美元，5 万张约 24 美元/月；对 5% 的记录用更强模型重试，增加很少。预算的大头是复核人力。

> [!TIP] 面试技巧
> - 先讲模式设计、校验和修复循环；说明仅靠提示词不是可靠性策略。
> - 把置信度解释为组合信号（校验、一致性、原文引用依据），并按错误代价确定人工复核队列的规模。
> - 在标准集上按字段评估 P/R/F1，为关键字段设门槛，并监控漂移和直通处理率。
