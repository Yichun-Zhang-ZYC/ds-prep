## Why it matters
You cannot improve an LLM app you cannot measure. An offline eval set (a "golden dataset") lets you compare prompts, models and retrieval changes before shipping, and catch regressions in CI. Interviewers ask how to build one, how big it must be, and whether a 5-point gain is real.

## Concept
**Sources of cases**:
- **Production logs**: sample real queries (anonymized); best reflection of the true distribution.
- **Expert-written** cases for high-stakes or rare scenarios.
- **Synthetic** cases generated by an LLM from your documents, then human-reviewed; cheap but skews easy and clean.
- **Adversarial / edge cases**: ambiguous, out-of-scope, prompt injections, empty or long inputs, multilingual.
- **Failures**: every production bug or bad thumbs-down becomes a new case (the eval set grows like a regression suite).

**What each case holds**: input, context (if any), and a way to judge: a reference answer, required facts or must-not-say lists, an expected tool call or SQL result, or a rubric. Prefer **checkable** criteria (exact match, schema validity, executed result) over subjective ones when possible; add tags for **slices** (topic, language, difficulty, user segment).

**Size and statistics**: start with 50-200 well-chosen cases and grow. For a pass rate $\hat p$ on $n$ independent cases the standard error is $\sqrt{\hat p(1-\hat p)/n}$; to estimate a rate within margin $e$ at 95% confidence, $n \approx 1.96^2\,p(1-p)/e^2$ (worst case $p = 0.5$). Use the **Wilson interval** for small $n$ or rates near 0 or 1. Compare two variants on the *same* cases with a paired test (e.g. McNemar), since the same cases are shared.

**Hygiene**:
- Keep a **held-out test split** you do not tune prompts on; otherwise you overfit the eval.
- **Contamination**: no eval cases in few-shot examples, fine-tuning data or retrieval corpus.
- Version datasets and pin judge/model versions so runs are comparable; dedupe near-duplicates.
- Report **per-slice** results; an average can hide a collapsed segment.
- Run in CI as a gate; set temperature 0 or repeat runs to measure nondeterminism.

## Worked example
A margin of $\pm 5\%$ at 95% confidence with $p = 0.5$: $n = 1.96^2 \cdot 0.25 / 0.05^2 = 384.2 \to 385$ cases.

Prompt v1 passes 96 of 120 cases (80%); Wilson 95% interval is about $[72\%, 86\%]$. Prompt v2 passes 102 of 120 (85%); interval about $[78\%, 90\%]$. The intervals overlap heavily, so a 5-point gain on 120 cases is not convincing evidence on its own. Run a paired comparison on the same cases or expand the set. If v2 fixes 12 cases and breaks 6, McNemar looks at the 18 discordant cases: 12 vs 6 is not significant (two-sided $p \approx 0.24$).

> [!TIP] Interview tips
> - Mention sources (prod logs, expert, synthetic + human review, failures) and that the set grows with bugs.
> - Quote the sample-size formula and the Wilson interval; say a 5-point gain on ~100 cases is noisy.
> - Keep a held-out split, avoid contamination, and report per-slice.
