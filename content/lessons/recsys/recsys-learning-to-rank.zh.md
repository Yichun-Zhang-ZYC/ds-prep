## 为什么重要

排序模型决定了用户在搜索、信息流和推荐中最先看到什么。面试官会让你对比 pointwise、pairwise 和 listwise 损失，并说明为什么直接优化 NDCG 很困难。

## 概念

排序学习（LTR）训练一个打分函数 $f(x_{q,d})$，使每个查询（或用户）$q$ 下，相关文档的分数高于不相关文档。只有列表内的**顺序**才重要。

- **Pointwise**：把每个物品独立当作回归或分类（例如用对数损失预测点击概率）。简单且校准，但忽略了列表结构，以及只有相对顺序才重要这一点。
- **Pairwise**：从满足 $y_i > y_j$ 的样本对 $(i, j)$ 中学习。RankNet 损失：$\log(1 + e^{-(s_i - s_j)})$。它直接惩罚顺序错误的样本对（BPR、RankSVM 的 hinge 损失是变体），但对所有样本对一视同仁，因此第 100 位的错误与第 1 位的错误同等重要。
- **Listwise**：优化整个列表的函数：ListNet（分数分布与标签分布之间的交叉熵），或 **LambdaRank/LambdaMART**，后者把每个样本对的梯度乘以 $|\Delta \text{NDCG}|$（交换两个物品带来的变化），因此靠前位置更重要。

**为什么不直接优化 NDCG？** 它关于分数是分段常数（需要排序），所以梯度为零或未定义。LambdaRank 通过不依赖显式损失而直接定义梯度（lambda）来绕开这一点。**LambdaMART** = 使用梯度提升树的 LambdaRank，是多年来的工业默认方案（XGBoost `rank:ndcg`、LightGBM `lambdarank`）。

**实践要点**：特征来自查询-文档对（BM25、CTR、embedding 相似度、新鲜度）；标签来自人工评级或点击，而点击数据存在**位置偏差**，因此要使用逆倾向加权，或仅在训练时把位置作为特征。在推荐中，pointwise 多任务排序器（预测点击、点赞、观看）加加权求和，仍是最常见的生产方案。

## 示例讲解

分数 $s = [2, 1, 0]$、标签 $[2, 1, 0]$ 时，三个样本对顺序都正确：$(0,1)$ 间隔 1，$(0,2)$ 间隔 2，$(1,2)$ 间隔 1。RankNet 损失分别为 $\log(1+e^{-1}) = 0.313$、$\log(1+e^{-2}) = 0.127$ 和 $0.313$，平均为 $0.251$。把分数反转为 $[0, 1, 2]$，所有间隔都变为负：损失为 $\log(1+e^{1}) = 1.313$、$\log(1+e^{2}) = 2.127$、$1.313$，平均 $1.585$。

## 检验理解

```quiz
{
  "id": "q1",
  "question": "在 RankNet 的成对梯度之上，LambdaRank 增加了什么？",
  "options": [
    "更大的学习率",
    "把每个样本对的梯度按交换该对所引起的 |NDCG 变化| 缩放",
    "不同的模型架构",
    "去掉 sigmoid"
  ],
  "explanation": "靠近顶部的交换对 NDCG 的影响更大，因此这些样本对得到更大的 lambda。这使成对损失朝向列表级指标。"
}
```

```quiz
{
  "id": "q2",
  "question": "为什么不能直接对 NDCG 做梯度下降？",
  "options": [
    "NDCG 对二值标签没有定义",
    "它依赖排序顺序，而顺序关于分数是分段常数，所以几乎处处梯度为零",
    "NDCG 总是 1",
    "它在线上服务时需要标签"
  ],
  "explanation": "分数的微小变化要么保持顺序（梯度为零），要么翻转顺序（不连续跳变）。因此使用 LambdaRank 或平滑近似等替代方法。"
}
```

> [!TIP] 面试技巧
> - 定义三类方法及其弱点：pointwise 忽略顺序，pairwise 忽略位置，listwise 更难优化。
> - 提到 LambdaMART 是强力的默认选择，并解释 |delta NDCG| 加权。
> - 谈到点击日志中的位置偏差，以及如何去偏（IPS、位置特征、随机交换）。
