## 为什么重要

矩阵分解（MF）赢得了 Netflix Prize，是所有基于 embedding 的推荐系统的祖先。面试官会问目标函数、SGD 与 ALS 如何训练，以及它如何处理缺失数据。

## 概念

用用户因子 $p_u \in \mathbb{R}^d$ 和物品因子 $q_i \in \mathbb{R}^d$（例如 $d = 32$）近似稀疏评分矩阵 $R \approx P Q^\top$。预测是点积，可加偏置：
$$\hat r_{ui} = \mu + b_u + b_i + p_u^\top q_i$$

**目标函数**：只在**已观测**的条目上最小化平方误差，再加 L2 正则：
$$\min \sum_{(u,i)\in \Omega} (r_{ui} - \hat r_{ui})^2 + \lambda(\|p_u\|^2 + \|q_i\|^2)$$
记 $e_{ui} = r_{ui} - \hat r_{ui}$，一步 **SGD** 为 $p_u \leftarrow p_u + \eta(e_{ui} q_i - \lambda p_u)$，$q_i \leftarrow q_i + \eta(e_{ui} p_u - \lambda q_i)$（更新 $q_i$ 时使用旧的 $p_u$）。

**ALS**（交替最小二乘）：固定 $Q$，每个 $p_u$ 都有闭式的岭回归解；然后固定 $P$ 求解 $Q$。每个半步都可以完全并行，并且 ALS 能很好地处理隐式反馈，这也是 Spark MLlib 使用它的原因。SGD 更简单，更适合流式/在线更新。

**为什么优于近邻 CF**：它把稀疏矩阵压缩成稠密的低秩因子，能泛化到没有共同评分的用户-物品对，打分只是廉价的点积。**陷阱**：秩 $d$ 和 $\lambda$ 必须在留出数据上调参；显式反馈损失中绝不能把缺失当作零；新用户/新物品没有因子（冷启动）。

## 示例讲解

一条观测评分 $r = 1$，$p = [1, 0]$，$q = [0.5, 0.5]$。预测为 $0.5$，所以 $e = 0.5$。取 $\eta = 0.1$、$\lambda = 0$：$p \leftarrow [1 + 0.1\cdot 0.5\cdot 0.5,\; 0 + 0.1\cdot 0.5\cdot 0.5] = [1.025, 0.025]$，$q \leftarrow [0.5 + 0.1\cdot 0.5\cdot 1,\; 0.5 + 0] = [0.55, 0.5]$。新的预测为 $1.025\cdot 0.55 + 0.025\cdot 0.5 = 0.576$，更接近 1。

> [!TIP] 面试技巧
> - 能默写目标函数和 SGD 更新，并说明损失只使用观测条目。
> - 对比 ALS（闭式、可并行、适合隐式数据）与 SGD（简单、在线、适合大规模稀疏数据）。
> - 陷阱：用按时间划分的验证集调 $d$ 和 $\lambda$；MF 无法为新用户/新物品打分，需要兜底方案（冷启动）。
